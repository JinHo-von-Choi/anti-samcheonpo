# 삼천포 사용 지침

삼천포는 AI 코딩 에이전트의 헛짓(같은 검사 반복, 요청 범위 이탈, 같은 실패 반복, 허위 완료, 진척 없는 지출)을 실행 결과로 판정해 알리고, 경고를 무시하면 실행 전에 막는 로컬 하네스다. 모델을 호출하지 않고 기록은 로컬에만 둔다.

## 1. 설치와 연결

순서대로 하고, 각 단계의 결과를 확인한 뒤 다음으로 넘어간다.

1. 설치 여부 확인: `samcheonpo --version`, `samcheonpo-hook --version`. 두 버전이 같아야 한다.
2. 없으면 GitHub Releases에서 `samcheonpo_<버전>_linux_amd64.tar.gz`와 `SHA256SUMS`를 받는다.
   ```bash
   sha256sum -c SHA256SUMS
   tar -xzf samcheonpo_<버전>_linux_amd64.tar.gz
   mkdir -p ~/.local/bin && install -m 755 samcheonpo samcheonpo-hook ~/.local/bin/
   ```
   두 파일은 같은 폴더에 둔다. Linux x86-64 외 플랫폼은 `go install`로 설치할 수 있지만 실제 실행은 확인되지 않았다고 사용자에게 알린다.
3. 에이전트 연결: `samcheonpo install --agent claude` (또는 `codex`, `opencode`). 기존 훅과 상태줄은 보존된다.
   - "이미 설치되어 있다"가 나오면 `samcheonpo uninstall --agent <같은 에이전트>` 후 다시 설치한다. 업그레이드 때 플러그인 파일을 갱신하려면 이 절차가 필요하다.
4. 점검: `samcheonpo doctor --agent <에이전트>`. `error` 항목이 없어야 한다.
   - `ledger: 원장 무결성/스키마 확인 실패 (읽은 버전 N)`는 업그레이드 직후 원장이 아직 갱신되지 않은 상태다. doctor는 원장을 읽기만 한다. `samcheonpo sessions`를 한 번 실행하면 갱신된다. 원장을 지우지 않는다.
5. 새 에이전트 세션부터 적용된다고 사용자에게 알린다.

설치·연결·제거는 사용자 환경 설정을 바꾸는 일이다. 사용자가 요청했을 때만 한다.

## 2. 설정

- 사용자 설정: `~/.samcheonpo/config.yml`. 프로젝트 설정: `.samcheonpo.yml` (`samcheonpo init`으로 생성).
- 프로젝트 설정은 사용자 설정을 약하게만 바꿀 수 있다. 실행할 외부 프로그램(`iron_laws.path`), 알림 목적지(`notify.push`), 판정 모델 연결(`detectors.s3_drift.judge`), 실험 모드(`experiment.enabled`)는 사용자 설정에서만 켜고 지정한다. 이것들을 켜려고 프로젝트 설정을 고치지 않는다.
- 기본값을 바꿀 이유가 없으면 그대로 둔다: `rollout.mode: recommend`, `escalate_max_blocks: 3`, `contract.draft: off`, 실험 모드 꺼짐.

## 3. 작업 중 경고를 받았을 때

삼천포 경고는 관측 사실이다. 지시문으로 대하지 말고, 근거를 확인해 다음 행동을 바꾼다.

| 경고 | 할 일 |
| --- | --- |
| 같은 검사를 변경 없이 반복 (`s1.identical_rerun`) | 같은 명령을 다시 돌리지 않는다. 직전 실패 출력에서 원인 가설 하나를 골라 코드 한 곳을 고친 뒤 검사한다 |
| 이미 통과한 검사 재실행 (`s1.evidence_rerun`) | 다시 돌리지 않고 남은 일로 넘어간다 |
| 같은 오류 반복·이미 실패한 수정 재시도 (`s2.*`) | 지금까지 시도한 방법과 원인 가설을 짧게 정리해 사용자에게 보여 주고 다른 접근을 고른다 |
| 코드 밖 조건 가능성 (`s2.environment`) | 설치·서비스·권한·네트워크를 먼저 확인한다. 필요하면 사용자에게 할 일을 알리고 코드를 더 고치지 않는다. 사용자 승인 없이 서비스를 켜거나 패키지를 설치하지 않는다 |
| 요청 범위 밖 수정 (`s3.out_of_scope`) | 꼭 필요한 변경이면 이유를 먼저 설명하고, 아니면 되돌린다 |
| 보호 경로 (`s3.protected_path`) | 그 파일을 건드리지 않는 방법을 찾는다 |
| 시험 약화·오류 숨김·허위 완료 (`s5.*`) | 시험을 지우거나 약하게 바꾸지 않는다. 오류를 숨기지 않는다. 완료 조건이 실패한 상태에서 완료라고 말하지 않는다 |
| 같은 지점에서 계속 막힘 (`s6.capability_limit`) | 작업을 더 작은 단계로 나누거나 막힌 점을 질문 하나로 정리한다 |
| 진척 없는 지출 (`s8.*`) | 지금까지 한 일과 막힌 점을 정리해 보고하고 지시를 기다린다 |

실행이 "권고가 이미 전달됐는데 반복되어 이번에는 막았다"로 거부되면:

- 차단을 피하려고 명령 글자만 바꾸지 않는다(환경변수 덧붙이기, 래퍼 추가, 명령 목록으로 감싸기 등). 판정은 실제 실행 내용과 작업 폴더 상태를 본다. 이런 우회는 같은 낭비를 반복하는 것이다.
- 차단 사유와 이전 결과를 읽고 접근을 바꾼다.
- 판정이 틀렸다고 보이면 근거를 들어 사용자에게 말한다. 해제는 사용자가 `/samcheonpo:keep normal`(이 판정은 틀림) 또는 `/samcheonpo:keep now`(이번만 허용)로 한다. 에이전트가 대신 실행하지 않는다.

## 4. 작업 계약

기본은 관찰 전용이다. 사용자가 완료 기준을 하네스가 직접 확인하길 원하면 계약을 쓴다.

```yaml
# .samcheonpo/contract.yml
goal: 로그인 세션이 만료되면 재로그인 화면으로 보낸다   # 바뀔 동작을 사용자 말로 한 문장
done:
  - check: "pytest -q tests/test_session.py"            # 하네스가 직접 실행할 명령
  - manual: 만료된 토큰으로 접속하면 /login으로 이동한다  # 사람이 확인할 조건
scope:
  allow: ["src/auth/**", "tests/**"]
  protect: ["migrations/**"]
budget: {krw: 5000, minutes: 40}
```

- 초안은 에이전트가 쓸 수 있지만 수락은 사용자만 한다(`/samcheonpo:accept`). 초안은 실행 승인이 아니다.
- `.samcheonpo/contract.state.json`을 직접 쓰거나 고치지 않는다. 수락 기록은 사용자 키로 서명되며 에이전트가 쓴 기록은 인정되지 않는다.
- 수락 뒤 계약의 어느 항목(목표 포함)을 바꾸면 다시 수락해야 한다. 목표를 바꿔 범위 이탈을 정당화하지 않는다.
- 완료 여부는 `samcheonpo cmd check`(또는 `/samcheonpo:check`) 결과로 말한다. 수동 조건은 사용자가 확인하기 전까지 미완료다.

## 5. 상태 확인과 되돌리기

- 상태줄 맨 앞 상태: `순조로움`(진척 근거 있음), `지켜보는 중`, `지금 끼어드세요`, `확인 불가`(관측 누락·저장 실패·기한 초과). 경고가 없다는 것을 진척으로 보고하지 않는다.
- 요약: `samcheonpo cmd summary` (요청한 일, 지금 하는 일, 끝난 것, 막힌 것, 쓴 돈).
- 되돌리기: AI가 쓰기 도구로 바꾼 파일을 마지막으로 검사가 통과한 시점으로 되돌린다.
  1. `samcheonpo cmd rollback`으로 미리보기를 보여 준다.
  2. 사용자가 원할 때만 `samcheonpo cmd rollback apply`를 실행한다.
  - AI가 쓴 뒤 사용자가 고친 파일, 셸 명령으로 바뀐 파일, 1MB 넘는 파일은 대상이 아니다. 데몬이 다시 시작되면 기준이 사라진다.

## 6. 회고와 보고

- `samcheonpo audit --since 30d`: 지난 기록에서 토큰이 진척·필요한 탐색·헛짓·기타 중 어디에 쓰였는지 집계한다. 모델을 호출하지 않는다.
- `samcheonpo receipt <세션> --evidence`: 세션 하나의 근거. 공유할 때는 `--share`.
- `samcheonpo gaps --since 30d --out <새 파일>`: 규칙이 놓친 의심 구간 후보. 판정이 아니다.
- `samcheonpo handoff <세션>`: 다른 에이전트나 새 세션에 넘길 첫 지시문. 원문이 들어 있어 공개 공유용이 아니다.

결과를 보고할 때:

- 원화는 "API 환산액"이라고 쓴다. 실제 청구액이나 절감액이라고 쓰지 않는다.
- 단가·사용량이 빠지면 0원이 아니라 "미확인"이다.
- 소급 분석의 맥락 이탈 판정은 추정이라고 밝힌다.
- "실시간이었다면 개입 N회"는 판정 후보 수다. 실제 개입이나 효과가 아니다.

## 7. 하지 않을 것

- 경고를 피하려고 명령·시험·설정을 조작하지 않는다.
- 사용자를 대신해 `keep`, `accept`, `rollback apply`를 실행하지 않는다.
- 원장(`~/.samcheonpo/ledger.db`)과 수락 기록을 지우거나 직접 고치지 않는다.
- 프로젝트 설정으로 외부 전송·외부 프로그램·실험 모드를 켜지 않는다.
- 삼천포 판정을 근거로 효과나 절감을 주장하지 않는다. 효과는 아직 입증되지 않았다.
