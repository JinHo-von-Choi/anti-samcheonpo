# 2차 구현 검증 — 2026-10-12

분석기 `samcheonpo-eval/0.5.0`, 원장 스키마 `11`의 작업 트리를 검증했다. 구현 범위는 [2차 규격](../spec/detection-phase2.md)에 있다. 실사용 정확도·독보성·비용 절감 효과를 합성 시험으로 주장하지 않는다.

## 구현 동작

- 실제 셸의 실패 검사로 Claude·Codex 세션 간 같은 작업의 3회 반복을 만들었다. 기록 전용과 명시적 선택 안내, L1 추정·비차단, 외부 세션 근거 구분, 동일 발견 중복 방지, 재시작, 읽기 취소·종료를 검사했다.
- 한 체크포인트의 두 검사와 처리 간격 안의 연속 검사 결과가 모두 탐지되는 것을 확인했다. 기존 회복 정책에 따라 처방은 하나만 대기하고 나머지 판정과 안내 보류 이유는 기록한다.
- 수락된 항목의 실제 실패 뒤 전체 완료 주장을 외부 모델 없이 후보로 기록했다. 공개한 부분 완료, 검사 실행만 완료한 보고, 완료 부정, 코드 문구를 제외했다. 관련 없는 검사·개정·요구사항, 이후 실패를 과거 주장에 연결하는 경우, 메타/도구 메시지와 과거 요청의 승인 재사용도 거부했다.
- 제안 고정 이후 학습 라벨·출처·검사 선택 범위·오류·변경 상태·분할·기준이 바뀌면 평가를 거부했다. 소표본, 같은 저장소/과제 계열의 상관 자료, 라벨 의견 불일치, 라벨 없음, 공개 회귀 자료로는 승격하지 못했다.
- CLI 통합 시험은 임시 원장의 학습 세션 1개와 holdout 160개에서 제안→평가→승격→임시 사용자 팩 설치→네이티브 Claude 로그 분석을 실행했다. holdout은 합성 양성 80개·음성 80개와 가상의 독립 라벨러 ID 2개다. 실사용 사람 라벨이나 성능 측정 자료가 아니다. 생성 팩은 실제 반복을 탐지했고 `effectiveness: unvalidated`를 유지했다.
- 설치 팩의 기본 기록 전용과 정확한 규칙 ID의 사용자 선택 안내를 검사했다. Claude 읽기 결과 본문을 원장에 보관하지 않고 지문으로 비교하며 Codex 결과와 셸 출력도 지문을 제공하는 것을 확인했다.

## 시험 환경과 결과

Linux amd64, Go 1.27.1. 서버의 기존 사용자 UID에서 파일 감시 자원 부족이 발생해 새 시험 세션의 `WatchUnavailable`이 참이 됐다. 구현은 불완전 관측을 근거로 판단을 보류했다. 기존 데몬의 fdinfo에서 많은 inotify 감시가 확인됐다. 이 환경 실패를 제품 회귀로 숨기거나 관측 가드를 제거하지 않았다.

운영 데몬·시스템 감시 한도를 변경하지 않고 소스 사본, 별도 UID(`nobody`), 전용 TMPDIR/빌드 캐시에서 전체 시험을 실행했다. `cmd`, `internal`, `plugins`의 Go 파일 및 go.mod/go.sum **386개가 원본과 일치**했다. 해당 묶음의 SHA-256은 `954928c2d428713cb0644e07b3a13c52fa7c7e3cc42cfd4ae3634c2a5a98027c`다. 모든 검사는 임시 원장과 설정을 사용한다.

- `go test ./...`: 전 패키지 통과. 최종 live 패키지 28.937초.
- `go test -race ./...`: 전 패키지 통과. 최종 live 패키지 191.077초, 경쟁 상태 보고 없음.
- `go vet ./...`: 작업 트리 통과.
- `gofmt -l internal cmd plugins`, `git diff --check`: 출력 없음.
- `scripts/check-conformance.sh`: **24/24 통과**.
- 격리 실제 프로세스 훅 검사: PreToolUse **200/200 응답**, 도구 수신 **200/200**, 시간 초과 0, 실패 0, 큐 누락 0. 프로세스 기동 포함 p95 **9.03ms**, 처리 p95 **2.49ms**, 콜드 스타트 **40.94ms**. 처리 구간 6ms 회귀 게이트 통과. 구간별 분위수는 서로 더하지 않는다.

일반 환경 재현 명령:

```sh
go test ./...
go test -race ./...
go vet ./...
sh scripts/check-conformance.sh
sh scripts/check-hook-budget.sh --p95-max 0 --handling-p95-max 6ms
```

감시 자원이 포화된 서버에서는 실제 소스의 접근 제한을 보존한 시험 사본과 별도 UID를 사용하고, `TMPDIR`, `GOCACHE`, `GOMODCACHE`, `GOPATH`를 시험 전용/읽기용 경로로 지정한다. 감시 실패 상태를 임의로 정상으로 바꾸지 않는다. 변경 내용을 실제 사용자 팩이나 실행 중인 데몬에 설치하지 않았다.

## 제품 효과의 한계

대표 과제의 실제 독립 사람 라벨, 두 에이전트의 장기간 안내 전달·관련 회복, 사전 등록 A/B 완료율과 감시 포함 총비용 효과는 별도 인수 자료가 필요하다. 구현 시험 통과와 제품 효과 검증을 구분한다.
