# 실제 에이전트 비교 프로토콜

상태: 실행 기록 v2, 독립 공개 채점 과제 22건(Python/JavaScript), 비용 귀속·과제 단위 비교 구현. 실제 유료 실험과 출시 효과는 아직 입증하지 않았다. 과제에는 수치·파싱·인코딩·경계·여러 파일 수정, 명세 세부 규칙·오래된 로컬 시험이 함정인 과제 6건, 헛돌기 쉬운 환경·모순 조건을 둔 과제 4건, 정상 음성 사례 2건이 있다. 공개된 회귀 과제는 비공개 holdout을 대신하지 않는다.

## 실행과 기록

`samcheonpo bench ab --config bench/ab.yml`은 과제·반복 블록마다 arm 순서를 seed로 섞는다. seed는 순서 재현용이지 원격 모델의 결정성 보장이 아니다. 실행마다 새 작업 복사본과 별도 SAMCHEONPO_HOME을 만든다. 명령은 복사본 안에서 실행되므로, 저장소 안의 파일(예: 플러그인 디렉터리)은 비교를 시작한 폴더를 뜻하는 `{root}`로 가리킨다. `{task}`는 과제 폴더, `{prompt}`는 과제 지시문으로 바뀐다. 결과는 run_id, seed, order, 에이전트·모델·정책 버전, 과제·채점기 해시를 기록한다. arm 설정의 agent_version/model/policy_version이 비어 있으면 해당 실행 조건은 미확인이다. 비용과 외부 채점 시간을 포함한 총예산 상한은 실제 실험 전에 별도 고정해야 한다.

Claude의 session_id와 Codex의 thread.started/thread_id를 해석한다. 실제 파일 내부 세션 ID, 작업 디렉터리, 파일 수정 시각을 확인하고 일치하는 transcript가 둘 이상이면 비용을 확정하지 않는다. 사용량 파싱 누락·미인식 단가·파일 부재도 `cost_known: false`와 사유로 남긴다. 비용 단위는 실제 청구액이 아닌 `transcript_api_equivalent`다. 구독 한도나 결제 절감액으로 해석하지 않는다.

실패·시간 초과 시행을 결과에서 제거하지 않는다. 알려진 실패 비용도 완료당 비용의 분자에 포함한다. 한 건이라도 비용이 누락됐거나 완료가 0건이면 완료당 비용은 미확인이다. 실제로 측정된 0원과 미확인을 `cost_per_verified_known`으로 구별한다. 재수입한 시행·같은 세션의 중복 비용, 서로 다른 프로토콜 버전 혼합은 report에서 거부한다.

## 독립 채점

과제의 `grader/`를 에이전트 작업 복사본 밖에 복사하고 그 폴더에서 check 명령을 실행한다. `BENCH_REPO`는 제출물 경로, `BENCH_GRADER`는 채점기 경로다. 과제 원본과 채점기를 실행 전후 해시로 비교한다. median 과제는 제출물의 unittest를 사용하지 않고 외부 기대값을 비교한다. 제출물 코드를 별도 프로세스에 실행해 `exit(0)`만으로 빈 결과를 통과시키지 않는다.

이 격리는 제출물 테스트를 약화하는 일반적인 실수를 막는 수준이다. 같은 OS 사용자로 실행하는 악의적 프로세스를 막는 sandbox가 아니다. 공개 과제의 기대값도 진짜 비공개 holdout이 아니다. 대외 비교에는 격리된 실행 권한과 별도의 비공개 평가 과제가 필요하다. grader 폴더가 없는 구형 과제는 `independent_grader: false`로 표시한다.

## 비교 판정

성공률에는 Wilson 구간, 성공률 차이 하한에는 Wilson 기반 Newcombe 구간을 사용한다. 비열등 한계는 -5%p다. 30회 미만은 판정을 보류한다. 이 최솟값을 충족했다고 검정력이 확보되는 것은 아니며, 같은 과제의 반복을 독립 과제로 간주하면 안 된다.

비교는 같은 run/task/trial의 짝을 맞춘 뒤 과제 전체를 묶어 4,000번 재표집한다. JSONL 행 순서와 무관한 seed 73129를 기록하고, 기준군 외 비교 수로 Bonferroni 보정한 percentile 구간을 보고한다. 과제 내 반복을 독립 과제로 세지 않는다. `task.yml`에 `group`(원본 사건 ID)이 있으면 같은 그룹의 변형 과제들은 하나의 클러스터로 묶어 재표집하고 독립 과제 수도 그룹 수로 센다. 12개 과제·30개 짝 미만, 버전/독립 채점 누락, 짝 누락, 퇴화 구간은 판정 보류다. 모델·에이전트가 다르면 감시 정책 효과를 분리할 수 없어 보류한다. 표본이 작거나 대표성이 없을 때 bootstrap은 이를 해결해 주지 않는다. 구간에 따른 `meets_cost_goal`은 이 데이터의 탐색적 비교이며 제품 출시 승인이 아니다.

`monitor: none`은 운영자가 감시 비활성을 선언한 군이다. 전용 실험 홈에 원장이 생기면 선언 불일치로 비용을 보류한다. `monitor: samcheonpo`는 그 시행 전용 원장의 모든 판정 예약을 읽기 전용으로 합산한다. 미정산·미확인 비용·관측 누락은 0으로 바꾸지 않는다. 감시원 미선언·외부 감시 도구는 비용 미확인이다. 행의 `total_krw`는 에이전트 API 환산액, `monitor_krw`는 별도 감시 환산액이며 완료당 총비용·비용 구간은 둘 다 있어야 계산한다. 실패 시행 비용도 포함한다. 에이전트 구독 실제 청구 절감으로 해석하지 않는다.

사전 표본 수 계획은 `samcheonpo bench plan-sample --pilot-sd 0.2 --gap 0.05 --comparisons 1`로 실행할 수 있다. 별도 파일럿의 과제 단위 대응 차이 표준편차가 입력이며 alpha=0.05/power=0.8의 정규 근사에서는 독립 과제 쌍 126개가 나온다. 반복 126회가 아니고 비용 비율 검정력의 보장도 아니다. 22개 공개 과제로 무조건 효과를 입증할 수 있다는 뜻이 아니다. 표준편차 0·미확인은 계획에 사용할 수 없다.

방법 참조: [SciPy bootstrap 문서](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)의 대응 재표집·구간 정의. 이 구현은 외부 패키지를 설치하지 않는 Go 과제 클러스터 percentile 방식이며 BCa 구현이라고 주장하지 않는다. 개별 성공률 Wilson 구간은 기술 통계이고 출시 비열등 판정에는 독립 시행 가정을 그대로 적용하지 않는다.

예비 실험은 6개 과제 × 3개 군 × 2회 = 36회를 출발점으로 삼되, 분산 추정과 파이프라인 검증용이다. 이후 필요한 표본 수·중단 규칙·비용 한도를 먼저 확정한다. 유리한 시행만 남기거나 예산 초과 실패를 새 시행으로 바꾸지 않는다. 비개발자 관찰과 실제 실험 결과는 합성 단위 테스트 결과와 분리한다.

## 판정 공백 표본과 라벨

`samcheonpo gaps --since 30d --out <새파일>`은 현재 규칙이 헛짓으로 세지 않은 의심 구간(진척 없는 검증 연속, 문서만 바꾼 뒤 검증, 같은 상태의 리뷰·하위 에이전트 반복)을 원장에 쓰지 않고 뽑는다. 결과는 후보이며 판정이 아니다. 사람은 `samcheonpo label <세션>`으로 해당 범위를 표시하고, 라벨은 발생(`symptom`), 개입 정당성(`justified`: yes|no|unsure), 이후 확인 결과(`outcome`: resolved|unresolved|unknown) 세 축으로 남긴다. 표본 파일에는 요청 원문 일부가 들어 있어 공유하지 않는다.
