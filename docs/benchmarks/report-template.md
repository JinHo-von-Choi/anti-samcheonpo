# 비교 결과 보고서 양식

상태: 미실행 양식. 아래 빈칸을 0·성공·실험 결과로 해석하지 않는다. 공개 fixture 통과와 실제 에이전트/사람 관찰은 별개다.

## 사전 고정

- 실행 책임자·날짜·소스 커밋:
- 과제 모집단·선정/제외 기준·언어·저장소/과제 계열:
- 비공개 보류 자료 관리 주체·동결 시점·분할 파일 SHA256:
- 기준군(무개입/단순 제한)·후보·비교 도구의 실제 지원 범위:
- 각 군의 에이전트/모델/정책/프롬프트/가격표/독립 채점 버전 및 해시:
- seed·블록 수·순서·관찰 기간·중단 규칙:
- 별도 파일럿 표준편차·검정력/표본 수 계획 및 한계:
- 총비용/시간 상한·시행 상한·감시/채점/재시작/인수인계 비용 범위:
- 실제 청구/API 환산/정액 한도 중 비용 단위:

## 재현 명령과 산출물

```sh
samcheonpo bench plan-sample --pilot-sd <별도파일럿값> --gap 0.05 --comparisons <비교수>
# 유료 시행은 별도로 승인한 설정·상한에서만 실행
samcheonpo bench ab --config <사전고정설정> --tasks <동결과제> --out <새결과.jsonl>
samcheonpo bench report <결과.jsonl> --baseline off --format json
sha256sum <결과.jsonl> <설정> <분할파일> <보고서.json>
```

기록 경로·실행 명령·도구 버전·출력 파일 해시를 보존한다. 인증값이나 원문 프롬프트를 공개 보고서에 붙이지 않는다. 시행 재시도는 원래 실패/시간 초과 행을 지우거나 교체하지 않는다. 원시 자료는 접근 제한 저장소에 둔다.

## 결과 (각 지표의 분모와 누락 포함)

| 지표 | 관측값 | 분모/누락 | 구간/방법 | 판정과 한계 |
| --- | --- | --- | --- | --- |
| 독립 채점 완료율 | 미측정 | 시행·과제 수 | 대응 과제 단위 | -5%p 비열등 여부 |
| 완료당 총비용 | 미측정 | 실패·감시·복귀 포함 | 과제 클러스터 구간 | 20% 목표와 감소 방향을 구분 |
| 잘못된 강제 차단 | 미측정 | 모든 차단·미검토 | 전문가 이중 판정 | 분모 0은 무오류 증거가 아님 |
| 경고 오탐 | 미측정 | 모든 경고·미검토 | 판정자 일치도·조정 | AI 라벨은 정답 아님 |
| 방해 횟수/시간 | 미측정 | 관측 시간·중도절단 | 시간당 비율 구간 | 초기 목표 0.2회/시간 |
| 감독 비용 | 미측정 | 모델·주입 토큰·검사 시간 | 단위별 | 계측 누락은 0 아님 |
| 실행 부담 | 미측정 | CPU·메모리·샘플 수 | 환경별 | 감시 포함 순효과 |
| 훅 지연 | 미측정 | warm/cold·유실·timeout | p50/p95/p99 | warm p95 10ms 목표 |

기술 통계·탐색적 비교·인과 효과를 구분한다. 공개 회귀 분할을 비공개 holdout으로 표시하지 않는다. 효과 구간과 표본 충분성, 누락 및 선택 편향을 함께 공개한다. 실제 실행하지 않은 경쟁 도구 수치는 비워 둔다.

## 단계별 적용 결정

1. `shadow`: 새 추정 규칙의 출력·방해를 관측한다. 자동 checkpoint/iron-laws 실행과 복구 권고를 하지 않는다. 사용자가 수락한 보호 경로와 명시적 예산은 유지한다.
2. `recommend`: 현재 기본값. 규칙별 shadow 목록 밖의 규칙은 먼저 권고를 전달한다. 차단 승격 가능한 규칙에 한해 같은 세션·의도 개정에서 권고를 받은 뒤 같은 규칙·패턴·대상으로 다시 위반하면 세션당 `escalate_max_blocks`회까지 차단한다. 사용자가 오탐 처리한 규칙은 차단하지 않는다. 목표 카드 확인·명시적 check와 기존 보호/예산은 별개다.
3. `validated`: 사용자 홈 설정에 평가 보고서 SHA256를 규칙별로 선언한 경우만 차단 후보가 된다. 훅 능력이 없으면 차단하지 않는다. 해시 선언은 운영자의 추적 기록이지 제품이 보고서 진위를 인증했다는 뜻이 아니다. 기본 사전 승인 규칙은 없다.

문제가 관측되면 해당 추정 규칙의 선언을 제거하거나 shadow로 낮춘다. 프로젝트 설정은 사용자 단계보다 높이거나 새 근거를 승인할 수 없다. 실험을 위해 명시적 사용자 보호/예산을 해제하지 않는다. 자동 승격·모델 전환·권한 확대는 없다.

대기 반복(`s1.explicit_waiting`)과 진행 정체(`s8.progress_stall`)는 기본으로 기록만 한다. 사용자가 `rollout.recommend_rules`에서 안내를 켜면 가벼운 안내(L1/advice)까지만 제공한다. 평가 보고서 해시를 등록하거나 같은 경고가 반복돼도 두 규칙은 차단하지 않는다.

## 격리 코퍼스 보고

`samcheonpo eval corpus`는 저장된 기록을 다시 분석하는 명령이다. 입력 목록(manifest)에 정한 원본·계약·관측 자료를 먼저 분석하고, 별도로 준비한 정답 라벨로 채점한다. 사용자 원장을 열거나 기록에 들어 있는 명령을 실행하지 않는다. [입력 형식과 실행 예시](../spec/agenttime-reliability.md#격리-코퍼스-평가)를 따른다.

- 원본 공개 자료와 입력 목록·라벨·설정의 해시, 판정기·단가표 버전을 기록한다. 포함 조건(cohort 필터)과 과제별 조정용(train)·평가용(eval) 분할도 적는다.
- 전체 기록, 선택한 분할, 읽기에 실패해 제외한 기록의 수를 나눈다. 판단 조건을 갖춘 기록, 대상이 아닌 기록, 확인할 수 없는 기록도 구분한다. 정답 라벨이 없는 기록은 채점에서 제외한다.
- 대기 호출 추출, 안내 조건을 만족한 기록 수(`detected_runs`), 안내 설정까지 반영한 전달 후보 수(`deliverable_runs`)를 따로 보고한다. 실제 안내 출력과 사용자의 대응 여부는 별도로 확인해야 한다.
- 전체 기록과 판단 가능한 기록을 나눠 정밀도(precision)·재현율(recall)·오탐률(FPR), Wilson 신뢰구간을 제시한다. 분모가 0이면 비율은 null이다.
- 제공된 합성 기록 6건은 기능이 깨지지 않았는지 확인하는 시험이다. `effectiveness_validated=false`로 보고한다. 실제 효과를 확인하려면 독립 과제로 안내를 켠 경우와 끈 경우를 비교해야 한다. 이것이 G12 검증이다.

## 비개발자 관찰 (실제 참여자 5–8명)

- 사전 동의, 익명 참여자 ID, 개발 경험 범주, 설치 환경을 기록한다.
- 참가자가 도움 없이 설치→과거 감사→목표 카드 이해→경고 설명→복귀→결과 확인→제거를 수행하도록 관찰한다.
- 소요 시간, 막힌 지점, 오해한 문구, 개입 횟수, 진행자 도움을 구분한다. 발화 인용은 공개 동의를 별도로 받는다.
- “비용을 줄였나”를 유도하지 말고 경고가 무엇을 뜻하는지 자기 말로 설명하도록 요청한다.
- 참가자 수·완료 실패 원인·수정한 문구/흐름과 재관찰 결과를 적는다. 합성 페르소나를 실제 참가자로 세지 않는다.
- 소규모 관찰을 통계적 우월성으로 홍보하지 않는다.

## 미해결 및 출시 판단

미측정·실패·승인 대기·환경 미지원과 후속 담당자를 적는다. 본 양식 작성이나 CI 통과만으로 출시 효과 관문을 닫지 않는다. 팀 정책·사례팩 같은 확장은 효용과 반복 수요가 확인된 이후에 별도 범위를 확정한다.
