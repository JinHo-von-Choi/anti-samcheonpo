# Codex 후속 사람 검토 절차

자동 채점은 과제 완료 여부만 판정한다. 경고가 타당했는지, 반복이 낭비였는지는 별도 사람 검토다. 현재 수집된 사람 응답은 0건이다.

## 독립 검토

기존 `eval prepare-review`로 완료된 원본과 원장에 결속된 검토 큐를 만든다. 미검토 대조 구간도 포함하며 탐지되지 않았다는 이유로 정상 라벨을 부여하지 않는다. 원본 경로·세션 ID·대화 내용이 들어 있는 자료는 접근 제한 폴더에 보관한다.

이번 시행만 수집하려면 저장소 루트에서 다음을 실행한다. 실행 결과의 정확한 세션 ID로 원본을 찾고, 안정된 사본을 만든 뒤 별도 원장에 감사한다. 기존 사용자 원장에는 쓰지 않는다. 자료가 부족하면 후보·대조의 실제 건수를 공개하며 목표 건수를 채웠다고 표시하지 않는다.

```sh
python3 scripts/codex_review_packet.py --binary /path/to/samcheonpo --results /private/run-one/trials.jsonl /private/run-two/trials.jsonl
```

두 검토자는 서로의 답과 실험군별 점수·비용을 보지 않고 먼저 판정한다. 원본의 문구·경로가 실험군을 드러낼 수 있으므로 완전한 눈가림을 보장하지 않는다. 각 검토자는 목표, 실제 변경, 관련 입력 변화, 검사 결과, 환경 오류 여부를 확인한다.

각 구간에 낭비 증상 또는 `none`, 개입 타당성 `yes/no/unsure`, 후속 결과 `resolved/unresolved/unknown`, 근거 사건 번호를 기록한다. 코드가 바뀐 뒤의 재검사, 환경 복구 확인, 장기 명령의 poll, 사용자 승인 대기는 반복 횟수만으로 낭비로 분류하지 않는다. 필요한 원본을 읽을 수 없으면 `unsure`다.

실제 검토자가 본인 식별자를 지정해 기존 명령으로 저장한다.

```text
samcheonpo label SESSION --labeler REVIEWER --queue PRIVATE/review-queue.json --dir PRIVATE/labels --start START --end END --symptom SYMPTOM --justified unsure --outcome unknown --note '직접 확인한 근거'
```

서로 다른 두 사람의 독립 답이 모인 뒤 불일치를 조정한다. 자동 생성 결과·실행 oracle은 `derived`로만 저장하며 사람 라벨과 섞어 정밀도·재현율이나 승격 근거를 만들지 않는다. 큐의 후보/대조 비율은 실사용 낭비 빈도가 아니므로 모집단 정밀도로 일반화하지 않는다.

## 비개발자 사용성 평가

참여자 5~8명을 모집한 뒤 역할·경험을 기록하고, 동의한 범위에서 과제를 수행하게 한다. 현재 참여자가 없어 아래 항목은 수집 양식이다.

- 처음 경고를 이해하고 다음 행동을 선택하기까지 걸린 시간
- 과제 완료 여부와 전체 소요 시간
- 경고를 무시하거나 도움을 요청한 횟수 및 그 이유
- 설명을 읽고 목표·현재 문제·다음 행동을 각각 자신의 말로 설명할 수 있는지
- 경고 중단이나 재개 기능을 찾을 수 있는지

질문은 “이 경고를 보고 무엇을 해야 한다고 생각했나요?”, “실제로 도움이 된 부분과 불필요한 부분은 무엇인가요?”, “다음에도 이 기능을 쓰겠나요? 이유는 무엇인가요?”로 통일한다. 실험군의 의도나 기대 효과를 먼저 설명하지 않는다. 가상의 참여자 응답을 채우지 않는다.

과제·참여자 순서를 기록하고 동일인 내 비교 시 순서를 바꾼다. 표본이 작으므로 관찰된 사례와 완료 비율을 보고하고 사용자 전체의 효과로 단정하지 않는다.
