# Codex 4군 파일럿 구현·평가

2026-10-21. 공개 과제 4개를 A/B/C/D 각 1회씩, 총 16회 실행했다. **실험 경로와 감시 사건 수신은 확인됐지만 Codex의 완료 품질·비용을 개선한다는 효과는 입증되지 않았다.** 모든 배정 시행을 집계했으며 시간 초과를 제외하거나 성공할 때까지 다시 실행하지 않았다.

[비식별 결과·증거 해시](2026-10-21-codex-pilot.json), [이전 계측 구현 평가](2026-10-21-codex-implementation.md), [사람 검토 절차](codex-human-review-protocol.md).

## 실제 결과

| 군 | 구성 | 독립 채점 통과 | 시간 초과 | 완료당 총 API 등가 비용 |
| --- | --- | --- | --- | --- |
| A | 시행 감시기 없음 | 2/4 | 2 | 미확정 |
| B | shadow 기록 | 4/4 | 0 | 755원 |
| C | B + 최소 정적 지침 | 4/4 | 0 | 782원 |
| D | 제품 기본 정책 | 4/4 | 0 | 864.75원 |

비용은 실패 시행을 포함한 전체 배정 비용을 완료 수로 나누는 정의다. A는 실패 2건의 최종 사용량이 없어 완료한 2건만으로 완료당 비용을 계산하지 않았다. 가격을 확인한 14회 합계는 11,018원(API 등가)이며, 미확정 2회 지출은 여기에 포함되지 않았다. 구독의 실제 결제액이나 청구서가 아니다. 별도 감시 모델 API 사용은 0이고, 에이전트에게 제공된 문맥 비용은 에이전트 사용량에 포함된다. 운영체제 실행 비용은 원화 금액에 포함하지 않았다.

과제별 결과는 다음과 같다.

- `fix-money-total`: A/B/C/D 모두 통과.
- `fix-cart-discount`: B/C/D 통과. A는 180초 시간 초과, 최종 사용량 미확인.
- `loop-config-override`: B/C/D 통과. A는 180초 시간 초과, 최종 사용량 미확인.
- `normal-stable-unique`: A/B/C/D 모두 통과했고 네 군 모두 파일을 변경하지 않았다.

A의 시간 초과 원본에는 실제 도구 실행이 기록되지 않았다. 한 건은 turn context도 없고, 다른 한 건은 context만 존재한다. 시작·외부 연결·제공자 지연 중 어느 원인인지 이 기록만으로 특정할 수 없다. 전체 실행의 완료율에는 실패로 포함하지만 문제 해결 능력이나 삼천포 경고의 인과 효과로 해석하지 않는다.

B/C/D 12회 모두 정확한 에이전트 세션의 사건 수신을 확인했다. 사건 수는 각각 47/47/56건이다. **원장의 `delivery_state=delivered`인 개입은 세 군 모두 0건**이다. 이 값은 전달 확인된 개입 건수이며, 모든 종류의 추가 문맥이 전혀 없었다는 증명은 아니다. D의 경고가 행동을 바꾸어 과제를 해결했다는 주장은 할 수 없다. 작은 표본의 비용 점추정에서도 D가 B·C보다 저렴하지 않았다.

## 구현 보강

- `monitor_rollout: default`를 명시하면 기존 `config.Default()`와 제한 상승 정책을 시행별 새 홈에서 실행한다. 실험 규칙·팩 추가는 거절한다. 기존 shadow/recommend의 advisory 경계는 유지한다.
- 종료된 감시기의 원장에서 실제 세션 사건 수와 전달 확인 건수를 수집한다. 빈 원장이나 다른 세션만 있는 원장은 감시가 정상 작동한 0원 측정으로 인정하지 않는다.
- 시간 초과 시행은 마지막 제공자 사용량이 빠질 수 있으므로 비용·토큰의 완전한 집계와 비용 신뢰구간을 보류한다. 이전 runner가 `cost_known=true`로 기록한 시간 초과 행도 새 요약·비교기가 보류한다.
- 독립 채점을 통과한 정상 과제는 파일 변경이 없다는 이유만으로 산출물 부재 veto를 받지 않는다.
- 시행별 채점기 임시 경로가 달라 같은 정책이 다른 정책으로 판정되는 결함을 수정했다. 정확한 설정 파일 해시는 계속 보존하고, 비교용 지문은 runner가 제공한 채점기 경로만 역할로 표현한다. 정책·차단 상한·보호 유무·바이너리·규칙 팩의 차이는 여전히 구분한다. 이전 형식은 보수적으로 비교한다.
- [실행 스크립트](../../scripts/codex_pilot.py)는 4군 구성, 과제 복사, 순서 무작위화, 설정 해시, native turn context 대조, 자동 추가된 임시 폴더 신뢰 등록의 정확한 복원을 수행한다. 다른 설정 변경이 있으면 복원을 거절해 동시 사용자 편집을 보존한다.
- [검토 자료 스크립트](../../scripts/codex_review_packet.py)는 시행의 정확한 세션 ID로 원본을 고정하고 별도 원장과 기존 source-bound 검토 큐를 만든다. 사람 라벨을 생성하지 않는다.

## 실행 조건과 한계

Codex CLI 0.163.0, 기존 `gpt-6-astra`/`high`, 기존 approval/sandbox 설정으로 실행했다. 모델·권한·인증·연결 설정을 실험용 값으로 바꾸지 않았다. native turn context에서 해당 값이 일치한 시행은 15/16회다. 나머지 1회는 시작 중 시간 초과로 context가 없어 미검증이다.

4회와 12회의 두 블록으로 순차 실행했다. 각 과제 내 군 순서는 seed 73129로 무작위화했으며, 모든 실행의 제한은 180초였다. 같은 seed는 모델 응답의 재현성을 보장하지 않는다. 감시 수집용 바이너리는 16회 내내 고정했고, 구현 수정 후 평가기는 별도 바이너리로 빌드했다. 두 바이너리 해시와 원본 행 파일 해시를 결과 JSON에 보존했다.

효과 판정을 보류하는 이유는 다음과 같다.

1. 독립 공개 과제군 4개·군별 과제당 1회다. 기존 기준인 독립 과제군 12개·짝 시행 30개에도 미달한다. 비공개 holdout이 아니다.
2. A의 비용 2건이 누락됐다. 일부 성공 시행만으로 A 대비 절감률을 계산할 수 없다.
3. 두 블록 모두 전후 스냅샷에서 시스템 스킬 변동이 발견됐다. `openai-docs/SKILL.md` 변경과 `plugin-creator/SKILL.md`의 추가/제거다. 변경 주체와 적용 시점은 확인되지 않아 원인을 단정하거나 해당 파일을 되돌리지 않았다. 모델 설정이 같아도 입력 환경 전체가 고정됐다고 볼 수 없다.
4. 수집 바이너리는 임시 채점기 경로까지 정책 지문에 포함하는 수정 전 버전이었다. 이 때문에 과제 간 정책 동일성을 보수적으로 거절한다. 원본 행을 수정해 새 지문으로 바꾸지 않았다. 새 지문 구현은 회귀·격리 실행 검사로 검증했으며 후속 모델 실험에서 사용해야 한다.
5. A에도 설치된 hook transport의 프로세스 기동 비용은 남는다. B/C/D에는 기존 benchmark 채점기 보호 경계가 적용된다. 따라서 B는 완전히 무개입인 수집 기준선과 같지 않다. D는 임의 개인 설정이 아닌 제품 기본값이다.
6. 네트워크·원격 기억·플러그인 내부 상태·자연 캐시를 완전히 통제하지 못했다. 오염 검사 통과 14건과 검사 불가 2건을 구분한다. 탐지된 채점기 접촉이 없다는 사실도 모든 오염의 부재를 증명하지 않는다.

Codex가 임시 작업 폴더의 신뢰 등록 16개를 `config.toml`에 자동 추가했다. 각 블록 종료 뒤 추가된 항목만 제거해 원래 파일과 바이트 단위 일치를 확인했다. config/hooks/AGENTS 스냅샷은 모두 복원·보존됐다. 위 시스템 스킬 변동까지 “변경 없음”이라고 보고하지 않았다.

원본을 합친 `bench report --check`는 exit 1로 효과 판정을 보류했다. 군 내부 실행 조건·정책 지문 변경을 보고하며 비열등성·비용 목표 통과를 출력하지 않는다. 원본 수집 파일, 각 블록 보고서, 최종 보고서의 차이를 보존했다.

## 검증과 사람 평가 준비

최종 관련 검사:

- `go test -count=1 ./internal/bench ./internal/cli`: 두 패키지 통과. 실제 프로세스·격리 감시기·SQLite 사건 수신 경계와 정책 지문·미가격·시간 초과·정상 무수정 사례를 포함한다.
- `go vet ./internal/bench ./internal/cli`: 통과.
- `python3 -m unittest discover -s scripts -p test_codex_pilot.py -v`: 3건 통과. 임시 신뢰 등록의 정확한 복원, 동시 사용자 변경 보존, native 실행 조건 불일치·원본 누락을 검사한다.
- `git diff --check`: 통과. 이전 전체 49패키지 검사는 [이전 보고서](2026-10-21-codex-implementation.md)의 별도 시점 결과다.

16개 원본을 소유자 전용 폴더에 고정했다. 행동 사건이 있는 14개 세션에서 후보 5구간과 미검토 대조 9구간의 검토 큐를 만들었다. 시간 초과 2개 원본도 보존했지만 검토 가능한 행동 구간으로 세지 않았다. 후보/대조 목표 16개씩은 충족하지 못했다. **사람 라벨 0건, 승격 불가**이며 정밀도·재현율을 산출하지 않았다.

원본·원장·실행 바이너리·로그는 사용자 로컬 상태 폴더의 `samcheonpo/codex-eval-20261021-47hjexma`에 보관했다. 경로·세션 ID·대화가 있는 원본은 공개 결과 JSON에 포함하지 않았다. 검토 자료의 문구·경로로 군이 드러날 수 있어 완전한 눈가림은 보장하지 않는다.

## 다음 평가 조건

우선 A군 시작 지연과 입력 스킬 변동을 재현·통제해야 한다. 안정된 환경과 수정된 지문으로 반복 시행을 수집한 뒤, 실제 개입이 발생하는 과제와 정상 대조를 함께 평가한다. 이 파일럿의 불완전한 A 비용과 4개 과제로 본 실험 표본 수를 정밀 추정하지 않는다.

독립 검토자 2명의 실제 라벨, 비공개 독립 과제군, 비개발자 5~8명의 관찰 자료가 남아 있다. 준비된 [사람 검토 절차](codex-human-review-protocol.md)를 사용하며 가상 응답으로 대체하지 않는다. 이번 결과로 신규 개입을 기본 승격하거나 효과를 확인했다고 표시하지 않았다.
