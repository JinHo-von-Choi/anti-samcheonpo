# 처음 사용하기

이 도구는 AI의 행동을 관측하고 원래 목표와 비교한다. AI가 항상 맞는지 판정하는 인증 도구가 아니며, 토큰의 API 환산액은 실제 청구액이나 절감액이 아니다.

## 설치와 확인

현재 소스 빌드가 기본 경로다. 저장소가 요구하는 Go 버전은 `go.mod`를 따른다.

```sh
go build -o ./bin/samcheonpo ./cmd/samcheonpo
go build -o ./bin/samcheonpo-hook ./cmd/samcheonpo-hook
./bin/samcheonpo doctor
```

두 파일은 같은 소스로 빌드해 같은 디렉터리에 둔다. 기존 연결은 이동한 파일을 자동으로 따라가지 않으므로 파일 이동 후에는 기존 연결을 제거하고 다시 설치한다. `doctor`는 설정을 수정하거나 데몬을 시작하거나 모델을 호출하지 않는다. 원장이 없다는 경고는 첫 실행 전에 정상일 수 있다. 읽기 오류·무결성 오류는 원본을 보존하고 해결해야 한다. 잘못된 설정의 원문이나 비밀값은 진단 출력에 포함하지 않는다.

릴리스 후보 압축 파일을 받은 경우 `SHA256SUMS`로 다운로드 무결성을 먼저 확인한다. Linux는 `sha256sum -c SHA256SUMS`, macOS는 `shasum -a 256 -c SHA256SUMS`를 사용한다. 체크섬이 같다는 것만으로 배포자 신원이나 프로그램 안전성이 인증되지는 않는다. 같은 파일에 들어 있는 두 실행 파일을 함께 배치한다. 플랫폼별 실제 검증 여부는 [지원 표](support-matrix.md)를 확인한다.

## API 키 없이 먼저 사용하기

```sh
samcheonpo audit --since 30d
samcheonpo sessions
samcheonpo receipt <세션ID>
```

이미 저장된 에이전트 기록을 읽는 감사는 모델을 호출하지 않는다. 사용량을 읽지 못했다면 0원 대신 미확인으로 표시한다. 기록이 없는 새 사용자라면 감사 결과가 비어 있어도 오류가 아니다.

실시간 연결은 사용할 에이전트 하나에만 설치한다.

```sh
samcheonpo install --agent claude
# 또는 codex, opencode, agy, hermes, openclaw
samcheonpo install --agent codex
```

기존 훅과 상태줄은 보존 대상이다. agy는 `~/.gemini/config/hooks.json`에 `samcheonpo` 훅 묶음을 더하고 다른 묶음은 건드리지 않는다. Hermes와 OpenClaw는 플러그인을 쓴 뒤 각 에이전트의 명령(`hermes plugins enable`, `openclaw plugins install`)으로 켜며, 제거도 그 명령(`hermes plugins remove`, `openclaw plugins uninstall`)으로 한다. 실행 중인 Hermes·OpenClaw 게이트웨이는 재시작해야 적용된다. Claude 설치에서 플러그인 CLI 호출을 직접 처리하려면 `--no-plugin-cli`를 쓴다. 이 경우 설정 파일을 썼다는 사실만으로 에이전트가 플러그인을 로드했다고 간주하면 안 된다. 에이전트의 플러그인/훅 신뢰 확인 뒤 새 세션에서 확인한다. 미확인 버전은 관찰 전용으로 시작한다.

## 목표 확인과 경고 읽기

기본은 관찰 전용이라 계약 초안을 요청하지 않는다. 계약 기반 진척 판정과 범위 강제를 쓰려면 `.samcheonpo.yml`에 `contract: {draft: on}`을 둔다. 그러면 첫 요청 뒤 목표 카드에 AI가 이해한 목표·완료 조건·범위가 표시된다. 초안 자체는 검사 실행 승인이 아니다. `/samcheonpo:accept`로 확인하거나 `/samcheonpo:edit <수정>`으로 고친다. 새 방향은 `목표 변경: <내용>`으로 명시할 수 있다.

경고에서는 관측 사실·미확인 사항·다음 행동·종료 조건을 구분해서 본다. 사용자에게 보이는 경고는 관측 두 줄 이내, AI에게 그대로 붙여 넣을 요청 한 문장, 선택지 순서로 나온다.

상태줄 맨 앞의 상태는 네 가지다.

| 상태 | 뜻 |
| --- | --- |
| 순조로움 | 마지막 진척 뒤 경고가 없고, 진척 근거가 있다. 수락된 계약이 있으면 완료 조건 검사가 하나 이상 통과했어야 하고, 계약이 없으면 추정 진척이면 된다. 추정 진척은 실패 중인 검증이 없을 때 코드가 새로 늘어난 쓰기, 실패가 줄어든 검증, 쓰기 뒤 처음 통과한 검증이다 |
| 지켜보는 중 | 진척 근거가 아직 없거나, 마지막 진척 뒤 안내(L1)가 있었다 |
| 지금 끼어드세요 | 마지막 진척 뒤 L2 이상 판정이 있거나, 해소되지 않은 L3 차단(보호 경로 등)이 있다 |
| 확인 불가 | 관측 누락(큐 포화), 기록 저장 실패, 기한을 넘긴 실행 전 판정이 있다 |

경고가 없다는 사실만으로 `순조로움`을 표시하지 않는다. 이미 통과한 검사는 입력·환경·개정이 같을 때만 재사용한다. 사용량 누락·원장 오류·큐 포화는 완료나 절감으로 해석하지 않는다. 판정 모델은 기본으로 꺼져 있으며 진단·설치가 외부 판정 정책을 켜지 않는다.

새 추정 규칙의 기본 단계는 `rollout.mode: recommend`다. `shadow`는 복구 권고·자동 checkpoint를 하지 않고 탐지 결과만 기록한다. 사용자가 수락한 보호 경로와 명시적 예산 한도는 어느 단계에서도 유지된다. 추정 규칙 차단은 사용자 설정의 `validated` 단계와 규칙별 평가 근거 선언이 모두 있어야 하며, 프로젝트가 스스로 승격할 수 없다. 예외로 `recommend` 단계에서도 같은 세션·같은 의도 개정에서 권고를 이미 받은 에이전트가 같은 규칙을 같은 대상(파일 또는 명령)에 같은 패턴으로 다시 위반하면 그 호출을 막는다. 동일 재실행·실패 반복·오류 은폐·시험 약화, 작은 변경 뒤 장시간 시험 재실행, CI 실패 뒤 재배포와 배포 횟수 초과, 실행 시간이 명시된 장시간 실행의 프로브 누락, 같은 입력으로 거부당한 명령의 재실행은 계약 없이도 승격되고, 범위·완료 조건·검증 비율처럼 계약에 기대는 규칙은 수락된 계약이 있을 때만 승격된다. 기대값 교체는 승격하지 않는다. 세션당 `rollout.escalate_max_blocks`(기본 3, 0이면 끔)회까지다. `/samcheonpo:keep normal`은 방금 본 판정을 오탐으로 기록하고, 현재 목표 개정 안에서 같은 규칙·같은 대상(파일 또는 명령)은 다시 막지 않는다. 다른 대상과 새 목표에는 적용되지 않으며 보호 경로와 예산은 그대로다. `keep now`는 이번 한 번만 넘기고, 같은 일이 다시 생기면 막기 전에 먼저 안내한다. 프로젝트 설정은 이 상한을 낮출 수만 있다. 자세한 평가 절차는 [보고서 양식](benchmarks/report-template.md)을 따른다.

## 코드 밖 원인과 수정 보류

실패한 명령의 출력과 종료 코드로 원인을 분류한다. 설치되지 않은 의존성·명령, 실행 권한 없음, 주소 해석 실패, 접속 거부, 권한 없음, 포트 점유, 인증 거부, 디스크 부족은 코드 밖 원인이다. 같은 명령이 작업 폴더 변화 없이 같은 코드 밖 원인으로 두 번 실패하면, 그 원인이 풀릴 때까지 소스 파일 쓰기를 실행 전에 보류하고 사유에 사람이 실행할 명령 한 줄을 담는다. 사용자에게는 "사람이 확인할 일: `npm install yaml`"처럼 표시된다.

- 의존성 선언 파일(`package.json`, `requirements.txt`, `go.mod` 등)과 `.samcheonpo/`는 보류 중에도 쓸 수 있다.
- 같은 명령이 통과하거나, 설치·서비스 기동처럼 환경을 바꾸는 명령이 성공하거나, `/samcheonpo:keep normal`로 풀면 보류가 해제된다.
- 이름 해석 일시 실패·시간 초과·연결 끊김 같은 일시 장애는 코드 밖 원인으로 치지 않고 재시도 기회를 둔다. 종료 코드 124(시간 초과)·137(강제 종료)도 코드 원인일 수 있어 보류하지 않는다.
- 보류 거부도 다른 차단과 같은 규칙을 따른다. 같은 원인의 귀띔이 먼저 전달되고, 세션당 차단 상한 안에서만 거부한다.

## 되돌리기

`/samcheonpo:rollback`(터미널에서는 프로젝트 폴더에서 `samcheonpo cmd rollback`)은 AI가 쓰기 도구로 바꾼 파일을 마지막으로 검사가 통과한 시점으로 되돌린다. 그런 시점이 없으면 AI가 이 세션에서 처음 쓰기 전 상태가 기준이다. 인자 없이 실행하면 미리보기와 계획 ID를 보여 준다. `apply <계획 ID>`로 실행하며, 미리본 뒤 파일이 바뀌어 계획이 달라졌으면 적용하지 않는다.

- 대상은 쓰기 도구의 입력으로 결과를 재현할 수 있고 실제 파일이 그 결과와 같았던 파일이다. 결과가 다르거나(동시 편집 가능) AI 편집 사이에 다른 편집이 섞인 파일은 소유권 불명으로 제외한다.
- AI가 마지막으로 쓴 뒤 사용자나 다른 명령이 바꾼 파일은 건너뛴다.
- AI가 새로 만든 파일은 삭제한다.
- 프로젝트 밖으로 이어지는 경로, 심볼릭 링크, 하드링크, 특수 파일, 셸 명령으로 바뀐 파일, 1MB를 넘는 파일, 세션 보관 용량(64MB)을 넘긴 뒤의 파일은 대상이 아니다. 대상이 아닌 파일도 미리보기에 이유와 함께 나온다.
- 바꾸기 전 내용은 `~/.samcheonpo/backup/rollback/<세션>/<시각>/`에 백업한다.
- 실행 결과는 원장의 `rollback` 표에 남는다.
- 마지막 진척 시점의 기준은 데몬 메모리에 있어 데몬이 다시 시작되면 사라진다. 대신 검사가 통과할 때마다 그 시점의 AI 소유 파일이 `.samcheonpo/snapshots/<id>/`에 기록되며(최근 5개, 64MB 상한), `/samcheonpo:rollback golden`으로 목록을 보고 `golden <id>`로 미리보기, `golden <id> apply <계획 ID>`로 그 시점으로 돌아갈 수 있다. 소유권 규칙은 같다. 다른 세션의 AI가 쓴 파일은 이 세션이 소유권을 확인할 수 없어 대상이 아니다.
- `.samcheonpo/`를 저장소의 `.gitignore`에 넣어 두면 기록이 커밋에 섞이지 않는다.

## 장시간 세션

오래 도는 세션에서 시간을 크게 잃는 행동은 따로 본다.

- 몇 줄 고친 뒤 오래 걸리는 시험을 바로 다시 돌리면 판정한다. 대상은 지난번 실행이 `expensive_check_sec`(기본 300초) 이상 걸린 것으로 측정된 시험이다. 바뀐 파일과 연결된 시험이 먼저 통과했다면 전체 시험 한 번은 허용한다. heredoc 안의 `subprocess` 호출이나 `/tmp/…-gates-run.py`처럼 매번 새 이름으로 만든 실행 스크립트로 돌려도 같은 시험으로 본다.
- 실행 시간이 명시된 부하·장시간 실행(`k6 run --duration 2h`, `locust -t 30m`)은 300초까지 바로 허용하고, 그보다 길면 같은 대상의 짧은 실행이 통과한 길이의 6배까지만 허용한다. 코드가 바뀌면 그 기록은 무효가 된다. `timeout 600 npm test`의 `timeout`은 상한일 뿐이라 실행 시간으로 보지 않는다.
- 에이전트가 `gh run watch/view/list`, `gh pr checks`, `glab ci`로 원격 CI 실패를 확인한 뒤 다시 배포하려면 재현 근거가 있어야 한다. CI가 지목한 실패 시험이 로컬에서 통과했거나, 전체 범위나 장시간 검사가 로컬에서 통과해야 한다. 직전 배포 뒤 고친 내용에 통과한 검사가 없거나, 브라우저 시험이 타이밍으로 실패한 상태이거나, 한 시간에 두 번 넘게 배포해도 판정한다. 태그가 바뀌어도 같은 판정으로 보므로 두 번째부터는 실행 전에 막힌다.
- 세션 활동 시간이 2시간이거나 토큰(입력·출력·캐시 쓰기)이 1천만이면 상태줄에 표시하고, 4시간이거나 3천만이면 계속할지 사용자에게 묻는다. 활동 시간은 이벤트 사이 공백이 30분을 넘는 구간을 빼고 센다.
- `detectors.s8_cost.ceiling_hours`·`ceiling_tokens`나 계약의 `budget.minutes`로 상한을 정하면, 넘는 순간부터 파일 변경·검사·명령 실행·서브에이전트 호출을 거부하고 읽기만 허용한다. `/samcheonpo:extend 2h`(토큰은 `20M`처럼 대문자)로 늘릴 수 있고, `keep`으로는 풀리지 않는다.

## 설정 권한

프로젝트의 `.samcheonpo.yml`은 사용자 설정(`~/.samcheonpo/config.yml`)을 약하게만 바꿀 수 있다. 실행할 외부 프로그램(`iron_laws.path`), 알림 목적지(`notify.push`), 판정 모델 연결(`detectors.s3_drift.judge`), 실험 모드(`experiment.enabled`)는 사용자 설정에서만 켜거나 지정할 수 있고, 프로젝트 설정은 끄기만 할 수 있다. 실험 모드는 기본으로 꺼져 있다. 탐지 기준과 개입 단계(귀띔 기준, 알림·일시정지 기준, 반복 대기, 종료 보류 횟수, 일시정지 조건)는 사용자 설정보다 느슨하게만 바꿀 수 있다. 검증 명령 목록(`verify_commands`)은 추가할 수 있다. 세션 상한(`ceiling_hours`·`ceiling_tokens`)은 예산과 같아서 프로젝트 설정으로 낮출 수만 있고 올리거나 없앨 수 없다.

## 사용자 전용 명령

`accept`, `edit`, `skip`, `keep`, `extend`, `rollback apply`와 세션 밖 `contract accept`는 사용자의 판단을 바꾸는 명령이다. 슬래시 명령(`/samcheonpo:...`)으로 실행하면 동작한다. 에이전트가 셸 도구로 같은 명령을 실행하면 실행 전에 거부한다. heredoc으로 파이썬이나 셸 스크립트를 실행해 같은 명령을 부르는 것도 거부하지만, heredoc으로 파일에 쓰는 문서 안에 명령 이름이 들어 있는 것은 실행으로 보지 않는다. 같은 OS 사용자로 도는 프로세스가 데몬 소켓에 직접 접속하는 것까지 막지는 않는다.

## Windows

Windows 10 1803 이상(유닉스 도메인 소켓 지원)이 필요하다. 검사 명령은 Git for Windows의 `bash`로 실행하므로 계약의 `check:`를 유닉스와 같은 문법으로 쓸 수 있다. Git for Windows가 없으면 `cmd.exe`로 실행되어 `test -s`, `&&`, 작은따옴표 같은 POSIX 문법이 같은 뜻으로 동작하지 않는다. `samcheonpo doctor`의 `shell` 항목이 어느 쪽인지 알려 준다. `bash.exe`를 직접 지정하려면 `SAMCHEONPO_SHELL`에 경로를 넣는다. System32의 `bash.exe`는 WSL 시작 파일이므로 쓰지 않는다.

데몬은 현재 사용자와 SYSTEM만 접근할 수 있는 폴더(`%USERPROFILE%\.samcheonpo\run`)의 유닉스 소켓으로 훅과 통신하고, 접속한 프로세스의 사용자 SID가 데몬과 같은지 확인한다. `SAMCHEONPO_HOME`을 프로필 밖으로 지정해도 새로 만드는 폴더에는 같은 접근 제한을 건다. 이미 있는 폴더의 권한은 바꾸지 않는다.

## 제거와 복구

```sh
samcheonpo uninstall --agent claude
# 설치한 다른 에이전트라면 동일한 --agent로 제거
```

설치 후 사용자가 바꾼 상태줄은 덮어쓰지 않고 충돌을 설명한다. 원장·영수증·사용자 기록은 연결 제거만으로 삭제하지 않는다. 실행 파일도 자동 삭제하지 않으므로 연결 제거 후 사용자가 배치한 두 파일만 직접 정리할 수 있다. 실패한 설치/제거 뒤에는 설치 기록과 백업을 보존하고 재설치를 반복하기 전에 진단한다.

Claude 플러그인은 생성 파일 해시가 일치하는 파일만 제거한다. 수정·추가 파일이나 생성 목록이 없는 구형 설치의 파일은 보존한다. Codex/Cursor 훅도 설치했던 항목과 같은 항목만 제거한다. 외부 Claude 플러그인 등록 해제가 실패하면 설치 기록을 지우지 않으므로 CLI의 등록 상태부터 확인한다. 설정 심볼릭 링크는 교체하지 않으며 대상의 실제 경로를 지정해야 한다.

Copilot/OpenCode의 단독 연결 파일도 설치 시 생성 해시를 기록한다. 이후 수정됐거나 구형 설치라 해시 기록이 없으면 자동 삭제하지 않고 오류로 안내한다. 임의로 설치를 반복해 덮어쓰지 말고 기존 연결 내용을 확인한다.

인수인계에는 `samcheonpo handoff <세션> --format json`과 `handoff inspect`를 사용한다. 이 JSON은 원문을 담은 로컬 자료이며 공개 공유용이 아니다.

개인정보 주의: 작업 카드의 목표·후속 요청·출처는 재시작/인수인계를 위해 로컬 원장에 보존된다. `store_raw_text: false`를 작업 카드와 짧은 이벤트 요약까지 비식별화하는 스위치로 해석하면 안 된다. 계약·로컬 원장·원문 인수인계는 비공개 자료로 다루고, 공유가 필요하면 `receipt --share`/`export --redact` 결과를 별도로 검토한다. 팀별 접근 제어·동의 사례팩은 아직 구현 완료 범위가 아니다.
