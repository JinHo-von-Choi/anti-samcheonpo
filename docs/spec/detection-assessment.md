# 탐지·비용·관측 범위의 분리

2026-10-12 구현. 분석기 버전은 `samcheonpo-eval/0.5.0`, 원장 스키마는 `11`이다. 실행 파일 배포·기존 데몬 교체·사용자 설정 변경은 이 작업에 포함하지 않는다.

## 표시와 진단

상태줄, 영수증, 세션 목록은 양수 비율을 `0%`로 반올림하지 않는다. 0–0.1%의 양수는 `<0.1%`다. HUD의 기존 정수 `waste_percentage`는 호환용이며 새 소비자는 `waste_ratio_text`, `waste_ratio_basis`, `assessment`를 사용한다. 가격을 모르는 사용량은 토큰 기준이고 분모를 모르면 비율도 미확인이다.

`assessment`는 확정 분류 사건, 추정 후보, 전체 판정, 기록 전용 판정, 비용 귀속 상태, 관측 범위와 완료 근거를 분리한다. 후보가 있어도 비용을 아직 분류하지 않았으면 `unattributed_findings`다. 후보 생성은 기존 비용 분류에 더하지 않는다. 수집한 이벤트 수만으로 전체 수집률을 주장하지 않는다.

`why SESSION`, `coverage SESSION --format json`은 기존 원장을 읽기 전용으로 연다. 당시 저장된 이벤트 결정과 intervention 전달 채널을 사용하며 현재 설정으로 과거 전달 상태를 다시 판정하지 않는다. 기록이 없으면 `rollout_unrecorded`다. 종료 결과, 작업 폴더 지문, 결과 지문은 전경 셸 이벤트에만 적용한다. 비셸 도구를 셸 누락률 분모에 넣지 않는다. 과거 완료 검사 상태를 현재 완료로 표시하지 않는다.

원장에 `event_observation`을 추가했다. 명령·출력·프롬프트를 복사하지 않고, 제어된 이유 코드, 진척 종류, 지문, 안전한 reliability 사실을 저장한다. 이벤트와 관측 메타데이터는 하나의 트랜잭션으로 추가한다. 완료 분석 스냅샷에도 진단 사실을 보존하되 기존 봉인의 정규 입력은 바꾸지 않는다. 구버전 조회에서는 없는 관측 테이블을 미확인으로 처리한다. 일반 쓰기 연결을 여는 시점에 기존 마이그레이션 절차로 갱신된다.

실행 중인 원장 본체만 복사해 백업으로 삼지 않는다. 기존 절차대로 SQLite backup 또는 프로세스 종료 후 DB/WAL/SHM의 일관된 사본을 사용한다.

## 목표와 진척

`intent.Work`는 구현·조사·조사 후 문서 작성·문서 작성을 구분하고 현황 파악·조사·결과 정리·변경·검증 단계를 표시한다. 이는 요청과 관측의 해석이며 실행 권한을 추가하지 않는다. “조사하고 플랜 작성”은 구현 작업으로 간주하지 않고, “그 플랜대로 구현 시작”은 구현으로 해석한다.

진척은 파일 활동, 새 도구 결과, 실제 통과 검사, 수락 기준의 현재 통과로 구분한다. 새 결과 지문은 내용의 새로움을 보여 주는 근사치이며 독립 반증의 품질이나 질문 해소를 확정하지 않는다. 파일 수·출처 수·에이전트의 완료 주장만으로 완료를 확정하지 않는다. 기존 진척·비용 정책은 유지하며 HUD에 별도 근거를 제공한다.

HUD에는 기존 `verification.Plan`도 제공한다. 과거 통과는 재사용 후보이고 입력·환경의 현재 동일성, 만료와 수동 조건을 검증하기 전에는 현재 통과가 아니다. HUD 조회는 새 검사를 실행하지 않는다. 추가 진단 집계는 이벤트 추가분을 접고 늦은 비용은 기존 무효화 캐시로 갱신하므로 반복 조회가 전체 이벤트를 재순회하지 않는다.

## 행동 구간의 후보

- `s2.behavior_loop`: 체크 ID 또는 정확한 실패 항목·오류 지문을 대상으로 반복한다. 실행 래퍼·출력 옵션이 달라도 같은 선택 범위의 같은 실패가 이어지면 후보가 된다.
- `s4.research_repeat`: 조사에서 내용이 같은 결과의 반복을 후보로 남긴다. 검색어나 출처가 바뀌어도 내용 지문이 같으면 같은 자료 후보로 본다.
- `s1.delegation_loop`: 같은 리뷰 대상·목적에 동일한 관측 결과가 반복되는 경우다. 결과 없는 위임은 판단 불가다.

입력·환경·명시된 환경 변수/폴더/시간 제한·실패 결과·검사 선택 범위·의도 개정이 바뀌면 이전 후보를 끊는다. 통과한 같은 검사도 실패 구간을 끊는다. 사용자 후속 메시지는 새로운 맥락으로 처리한다. 백그라운드·불명확한 환경 변화·flaky는 반복 판단을 유보한다. 보관 상한은 행동 대상 128개, 관측 결과 512개, 대상별 최근 이벤트 12개다.

유사성 지문은 L1 추정 후보만 만들며 `ExecFP`를 대체하지 않는다. 차단·검사 재사용은 기존 엄격한 실행 동일성과 선언된 검사 근거를 사용한다. 새 규칙은 기본 기록 전용이다. 사용자 설정에서만 선택할 수 있으며 프로젝트가 활성화 권한을 추가하지 못한다.

```yaml
# 사용자 config.yml의 명시적 선택 예시. 구현 작업이 이 설정을 작성하지 않는다.
rollout:
  recommend_rules: [s2.behavior_loop, s4.research_repeat]
```

이미 `shadow_rules`를 직접 지정했다면 안내할 규칙을 그 목록에서도 제외해야 한다. `validated_rules`에 평가 해시를 적어도 새 추정 규칙의 차단 권한은 생기지 않는다.

선택형 의미 판정은 [예산 규격](judge-budget.md)을 재사용한다. 구조화 쟁점과 근거 이벤트를 요구하고 `unknown`을 허용한다. 새 모델·제공자·외부 전송 정책은 켜지 않는다.

## 연결된 작업과 관련 회복

`task-coverage SESSION`은 기존 task/session/handoff 링크를 읽는다. 지문이 비슷하다는 이유로 다른 작업을 합치지 않는다. `includes_children` 부모의 자손을 제외해 합쳐진 로그와 하위 세션을 중복 계산하지 않는다. 순환 링크·중복 세션·혼합 task ID는 거부한다. 같은 개정·대상·결과·알려진 입력/환경/실행 맥락에서 여러 세션에 걸친 3회 이상의 반복을 후보로 반환한다. 이 조회는 실행을 차단하거나 인수인계를 자동 수행하지 않는다.

새 행동 후보의 회복 시도는 대상 해시에 연결한다. 관계없는 읽기나 다른 대상의 검사는 회복 기회에 포함하지 않는다. `no_recurrence_observed`는 관측 구간에서 재발을 보지 못했다는 뜻이며 문제 해결이나 비용 절감의 인과 증거가 아니다. 조사·반복 리뷰·부분 완료·반복 승인 요청에 맞는 제한된 다음 행동과 종료 조건을 제안하고 기존 회복 상한을 사용한다.

## 사람 신고와 개선 후보

`gaps --source transcript|ledger|all`은 원문이 없는 연결 도구의 원장도 조사한다. 기본값은 기존 transcript 방식이다. `label --start N --end M --symptom S1~S8|none`은 대화형 입력 없이 실제 존재하는 이벤트 구간을 신고한다. `--justified yes|no|unsure`, `--outcome resolved|unresolved|unknown`으로 개입 타당성과 후속 결과를 따로 표시한다. 이 구간 라벨을 전체 세션 검토 완료로 간주하지 않는다. 라벨은 접근 제한 파일로 저장한다.

`rules candidates --labels DIR --split FILE`은 출처 그룹이 격리된 `split/2`의 calibration 라벨만 집계한다. holdout의 내용은 학습 후보나 라벨 해시를 바꾸지 않는다. 출처와 라벨 해시, 독립 세션 수, 오탐·미해결 개입을 비식별 JSON으로 남긴다. 한 사람의 신고를 검증된 규칙으로 승격하지 않는다. 후보는 검토 자료이며 자동 정규식 학습·정책 반영·외부 전송은 수행하지 않는다.

`eval corpus`의 manifest에 `rules`를 지정하면 새 행동 규칙도 독립 라벨로 재생 평가할 수 있다. 기존 manifest의 기본 대상은 대기·정체 두 규칙으로 유지한다. 적용 근거가 없는 실행은 미상이고 라벨 없는 실행은 음성 사례로 바꾸지 않는다. 의미 판정은 별도 허용된 판정·요구 근거가 없으면 적용 여부도 미상이다.

## 효과 검사와 외부 내보내기

`bench report --success-margin .02 --cost-goal .15 --check`는 사전 지정 기준으로 성공률 비열등성과 감시 비용을 포함한 완료당 총비용의 신뢰구간을 검사한다. 기존 대응 과제 클러스터·출처 격리·버전 일치·독립 채점 검사와 최소 표본 요건을 유지한다. 감시 비용 누락이나 비교 조건 불일치·표본 부족이면 보류이며 `--check`는 실패 종료한다. 성공 과제에 든 비용만 선택적으로 더하지 않고 실패 시도 비용도 포함한다. CLI JSON은 기존 배열 모양에 지정 기준 필드를 추가했다.

`export SESSION --otel --redact`는 원장에서 로컬 OTLP 파일을 만든다. 원문·경로·명령·원래 대화/호출 ID를 제외하고 파생 판정·비용 기준·완료 미확인·관측 범위를 custom attributes로 제공한다. 수집기 주소를 설정하거나 네트워크로 전송하지 않는다. 기존 `--otel` 단독은 기존처럼 명령·경로를 포함할 수 있다. OTLP 입력의 transport 상태나 상태 누락을 실제 셸 종료 성공으로 바꾸지 않는다.

## 검증의 한계와 다음 인수 작업

합성 회귀와 Claude/Codex 파서 적합성 사례는 구현 동작을 검사한다. 이 자료로 실사용 정확도·오탐률·절감률·독보성을 주장하지 않는다. 별도의 대표 과제·사람 독립 라벨·사전 등록 평가 분할·허용된 실제 모델 A/B 실행이 필요하다. 두 네이티브 에이전트의 실제 안내 전달과 관련 회복, 충분한 완료율·총비용 신뢰구간이 아직 제품 효과 인수 조건이다.

세션 간 반복의 실행 중 안내, 요구사항–주장–검사 결과 그래프, 고정 규칙의 독립 평가·승격은 [2차 구현](detection-phase2.md)에서 연결했다. 대표 과제의 실사용 효과 검증은 별도다. Cursor/Copilot 개입이나 모델·제공자 자동 교체는 활성화하지 않았다.
