# 작업·검증 근거 v2 초안

상태: 내부 타입·원장·별도 봉인과 명시적 v2 계약의 검사 재사용을 구현했다. 버전 필드가 없는 기존 `contract.yml`은 Progress Contract v1이다. 작업 카드·세션 간 연결의 사용자 흐름은 구현 중이며 이 문서 자체가 쉘 실행 권한을 부여하지 않는다.

## 재사용을 명시한 계약

```yaml
spec: progress-contract/2
goal: 입력 파일의 검증 조건을 충족한다
done:
  - id: local-check
    check: test -s input.txt
    pure: true
    reuse:
      inputs: [input.txt]
      environment_files: [/usr/bin/dash]
      deterministic: true
      max_age_sec: 60
```

`environment_files`에는 실제 실행 파일·런타임·설정·의존성 파일을 포함한다. 예시 경로는 해당 시스템에서 실제로 사용하는 셸 경로로 바꿔야 한다. 경로는 glob이 아닌 구체적인 파일·폴더이며 심볼릭 링크는 거부한다. 네트워크·시간·난수·외부 DB 등에 의존하는 검사나 flaky 검사는 이 설정을 사용하지 않는다. 선언된 의존성이 완전하다는 보장은 사용자의 수락 범위이며 도구가 자동 증명하는 사실이 아니다.

입력 파일 내용과 환경 파일 내용, 환경변수 전체의 해시, 실행기 버전을 비교한다. 환경변수 원문은 저장하지 않는다. 지문 계산은 시간·파일 수·총 읽기 크기로 제한하며 확인 실패 시 캐시를 쓰지 않고 검사를 실행한다. `reuse`는 v1에서 거부한다. v2 검사 설정을 바꾸면 검사 해시가 바뀌므로 다시 수락해야 한다. 최대 유효기간은 1시간이다.

현재 재사용 캐시는 세션 안에서만 유지된다. 재시작·다른 세션의 통과를 자동 승계하지 않는다. 세션 간 작업 ID·근거 재연결은 별도 작업 카드/인수인계 흐름의 인수 조건이다.

## 식별과 의도

`task-intent/2`는 무작위 작업 ID, 프로젝트 식별자, 생성 시간을 가진다. 하나의 작업에는 여러 에이전트 세션을 연결한다. `(agent, session_id)`는 하나의 작업에만 귀속하며 부모는 같은 작업의 기존 세션이어야 한다. 부모 관계를 추측해서 사용량을 합치지 않는다.

의도 개정은 1부터 증가한다. 부모가 현재 개정과 일치해야 하며 원장 기록과 작업 생성은 같은 트랜잭션이다. 같은 ID의 같은 내용 재전송만 허용하고 다른 내용의 덮어쓰기는 거부한다. 사용자 이벤트의 세션·이벤트 ID·시간을 기록한다. 도구 출력과 가져온 문서는 사용자 의도 개정의 출처가 될 수 없다. 출처는 텍스트 내용이 아니라 수신 어댑터가 지정해야 한다.

개정 생성은 항상 초안이다. 실행 승인은 기존 계약 파일·검사 해시에 대한 별도 수락 절차를 따른다. 사용자 요청이 바뀌면 기존 승인을 새 검사에 전용하지 않는다.

## 검증 근거

`verification-evidence/2` 키는 작업 ID, 개정, 검사 ID, 명령 해시, 관련 입력 해시, 환경 해시, 실행기 버전으로 구성한다. 빈 값은 미확인이지 모든 값과 일치하는 값이 아니다.

근거는 원본 세션·이벤트 ID, 관측 시간, 만료 시간, 결과 해시와 완전성·통과·종료 코드·시간 초과·부작용·불안정·수동 여부를 보존한다. 성공한 검사가 동일 키이고 유효기간 내일 때만 재사용 후보가 된다. 부작용, 불완전 출력, flaky, 시간 초과, 실패, 수동 확인은 자동 통과 캐시가 될 수 없다. 미래 시각의 근거도 재사용하지 않는다.

입력 지문에 포함되지 않은 외부 서비스나 환경 의존성이 있으면 키를 완전하다고 선언해서는 안 된다. 해시를 만들었다는 사실과 의존성을 모두 관측했다는 사실은 별개다.

## 반복 검사 종료선

반복 검증 경고의 `verification_plan`은 검사별 상태, 근거 ID, 출처 이벤트 ID, 만료 시각을 담는다. 훅 경로에서는 파일을 다시 해시하지 않으므로 과거 통과는 `candidate`이지 현재의 `reusable`이 아니다. 과거 근거만으로 명령을 차단하거나 목표 완료를 선언하지 않는다. 관측된 변경·개정 변경 뒤의 근거와 만료·불완전·flaky·부작용 근거는 후보로 표시하지 않는다.

명시적 `check`와 기존 체크포인트 Runner가 현재 입력·환경 지문을 확인한 경우에만 재사용 통과와 검사별 `stop_reason`을 제공한다. 이 시점에 같은 검사 반복이 불필요하다는 뜻이며, 이후 변경·실패·만료가 있으면 다시 확인해야 한다. 수동 조건은 `manual`로 남으며 자동 검사 종료와 전체 목표 완료는 다르다. 수동 조건만 있는 계약도 자동 실행 없이 확인 대기로 안내한다.

경고에는 조건부 종료 안내를 넣되 사실 전용 비교군에는 처방을 추가하지 않는다. 이 설계는 기존 실험 비교군의 의미를 유지하며 훅마다 지문 계산을 반복하지 않는다.

## 원장과 봉인

SQLite migration 0003은 기존 session/event와 별도로 task, intent_revision, task_session, verification_evidence, policy_decision을 만든다. 레거시 분석이 session 행을 교체해도 작업 근거가 삭제되지 않는다. migration 실패는 트랜잭션 전체를 되돌린다. 복구 전에는 프로세스를 종료하고 DB 및 WAL/SHM을 함께 보존하거나 SQLite backup API로 일관된 사본을 확보해야 한다. 실행 중인 DB 본체만 복사해 백업으로 삼지 않는다.

`evidence-ledger/1`의 직렬화·해시 체인은 변경하지 않는다. `evidence-ledger/2`는 별도 TaskSeal이며 v1 head, 작업 ID, 순서가 정해진 의도·근거 payload 해시를 묶는다. 원문 목표와 명령은 봉인에 넣지 않는다. 지원하지 않는 버전은 오류다. v2 검증은 원본 구조화 레코드가 필요하며 해시만으로 원래 목표를 복원할 수 없다.

같은 OS 사용자에게 원장 편집 권한이 있으면 해시를 다시 계산할 수 있다. 봉인은 변조 탐지와 재현성 자료이며 서명, 공격자 격리, 사용자 의사의 진위 증명이 아니다.
