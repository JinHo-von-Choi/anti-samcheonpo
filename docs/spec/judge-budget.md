# 선택형 의미 판정기의 예산

의미 판정기는 기존과 같이 기본 비활성이다. 제공자·모델·외부 전송 허용 정책을 이 기능이 바꾸지 않는다. 판정기 연결(`detectors.s3_drift.judge`의 provider, model, base_url, api_key_env)은 사용자 설정(`~/.samcheonpo/config.yml`)에서만 지정할 수 있다. 프로젝트 설정은 provider를 비워 끄기만 할 수 있다. 기존 Anthropic 기본 모델 선택은 실제 클라이언트와 예약 계산에서 공유한다.

`detectors.s3_drift` 설정:

```yaml
max_watch_cost_ratio: 0.02
max_watch_krw: 1000
max_judge_calls: 8
judge_timeout_sec: 10
max_judge_input_bytes: 8192
```

금액은 API 단가 환산값이다. 판정 자신의 비용을 뺀 계측 비용의 비율 상한과 절대 금액 상한 중 작은 값에 대해 **호출 전에** 예약한다. 입력 바이트 수에 framing 여유를 더하고 구조화 응답 출력 상한 256토큰을 적용한 추정이다. 실제 제공자의 청구 상한을 보장하는 계산은 아니며, 계측 비용이 예약액을 넘으면 후속 자동 호출을 중단한다.

호출 횟수는 1–128, 시간 제한은 1–60초, 입력 상한은 1–65,536바이트, 절대 상한은 1–1,000,000원 범위다. 잘못된 설정·단가 미확인·입력 초과는 호출하지 않는다. 입력·수락 계약·의도 개정·모델이 같은 중복 요청은 추가 과금하지 않으며, 진행 중에는 하나의 판정만 허용한다. Anthropic SDK의 자동 재시도도 사용하지 않는다.

## 판정 대상의 위험 등급

의미 판정은 삼천포가 하는 일 중 가장 비싸다. 그래서 모든 도구 호출마다 호출하지 않는다. **위험 등급이 높은 행동에서만** 예산을 쓴다.

등급은 그 행동이 무엇을 바꿀 수 있는지로 정한다. 얼마나 자주 하는지가 아니다.

| 등급 | 행동 | 예 |
|---|---|---|
| 낮음 | 읽기·탐색·조회 | 파일 읽기, 검색, 메모 파일 읽기 |
| 중간 | 파일 변경 | 파일 쓰기·수정 |
| 높음 | 명령 실행·자격증명·커밋·완료 주장 | 셸 실행, `.env`·`~/.ssh` 접근, `git commit`/`push`, 완료를 주장한 메시지 |

낮은 등급의 행동은 결정론적 탐지기가 처리한다. 그 비용은 0이다. 판단 예산을 넓게 얇게 나누는 것보다, 판단을 고위험 행동에 몰아 쓰는 편이 싸다.

이 등급 표는 `internal/policy/risk.go`에 있고, 그 값은 `GradeEvent`로 읽는다. 사용자 설정으로 바꾸지 않는다. 바뀌면 "같은 규칙이 같은 비용으로 돈다"는 성질이 깨진다.

한계가 있다. 등급은 **행동의 모양**만 본다. 위험 등급이 낮은 행동에도 위험한 지시가 들어 있을 수 있다. 그 경우는 S9 계열([지시 밀수](#))이 읽는다. 등급은 판정을 아끼기 위한 것이지, 판정을 대신하는 것이 아니다.

## 저장과 실패

SQLite migration 0005의 `judge_budget`은 에이전트/세션별 호출 수, 환산 지출, 예약, 요청 식별자와 미확인·초과 상태를 저장한다. 예약 저장 성공 전에는 모델을 호출하지 않는다. 재시작해도 호출 수와 이미 판단한 입력은 초기화하지 않는다.

실패·시간 초과·사용량 누락은 비용을 0으로 확정하지 않는다. 예약을 유지하고 해당 세션의 추가 자동 호출을 중단한다. 프로세스 중단 뒤 미완료 예약을 읽은 경우도 같다. 세션 종료 중인 호출은 취소하고 미확인 비용으로 기록한다. 뒤늦은 응답으로 이미 종료한 세션의 판정·봉인을 다시 쓰지 않는다.

서버가 취소 전에 비용을 청구했는지는 로컬 취소 성공만으로 알 수 없다. 영수증과 요약에 미확인을 표시하며, 예약액을 실제 지출로 대체하지 않는다. 원장 저장 실패 또한 정상 완료로 표시하지 않는다.

## 근거를 가진 후보

판정 입력은 목표, 수락된 계약이 있는 경우 완료 항목, 최근 이벤트 요약과 사용 가능한 이벤트 ID다. 계약 없이 진행하는 작업도 이미 설정된 선택형 판정기가 있으면 초안 목표를 평가할 수 있다. 에이전트의 완료·승인 요청 문장은 코드 블록을 제외한 짧은 자기 보고로만 전달한다.

응답은 `label: on_track|side_quest|drift|unknown`과 `issues`다. 쟁점 종류는 `requirement_substitution`, `partial_completion`, `repeated_permission`만 허용한다. 사용 가능한 ID를 인용하지 않은 쟁점은 버리고 자유 서술이나 모델이 제시한 명령·권한은 사용하지 않는다. 잘못된 응답은 `unknown`으로 남기며, 사용량은 판정 유효성과 별도로 정산한다.

2차 입력에는 요구사항 ID, 사용자 요청·에이전트 주장·도구 결과의 역할과 연결 상태를 갖춘 그래프도 제공한다. `issues`의 `requirements`, `claims`, `results`, `authorizations`는 사용 가능한 `evidence`에 포함된 실제 ID를 인용해야 한다. ID가 존재하는 것만으로 통과하지 않으며 역할·관련 요구사항·시간 순서를 검사한다.

완료 관련 모순 후보는 수락된 항목의 같은 작업·개정·입력·환경에 연결된 최신 실제 실패와 그 뒤의 전체 완료 주장이 있어야 한다. 단순 근거 부재, 공개한 부분 완료, 코드 블록 안의 완료 문구는 모순 근거가 아니다. 반복 승인 후보는 현재 사용자 요청이나 수락 확인이 필요하며 메타 메시지·도구 출력·이전 요청은 승인을 대신하지 못한다. 목표 밖의 새 배포·푸시 등을 묻는 문장은 이 후보에서 제외한다. 이 그래프도 실행 권한이나 최종 완료를 부여하지 않는다.

새 쟁점은 기본 기록 전용이고 L1 추정 후보다. 연속 drift도 L1 추정 안내이며 모델 판정만으로 차단·완료·권한을 확정하지 않는다. 전송 중 목표·계약 상태가 바뀌면 이전 목표의 답변은 폐기하되 발생한 비용은 보존한다.
