# 훅 시작과 버전 확인

## 경량 훅 프로세스

경량 훅 프로세스는 직렬 요청 하나만 처리하므로 `GOMAXPROCS(1)`로 실행한다. 사용자가 환경변수로 명시한 값은 유지하고, 별도로 기동하는 데몬의 병렬 실행 설정은 바꾸지 않는다. 지연 목표는 프로세스 기동을 포함한 end-to-end p95 10ms이며 `scripts/check-hook-budget.sh`로 측정한다. 한 번의 측정 통과를 모든 호스트·부하에서의 지연 보장으로 해석하지 않는다.

`SAMCHEONPO_HOOK_DIAGNOSTICS=1`의 `handling_ns`는 입력 읽기부터 응답 출력까지의 구간이며 프로세스 시작은 제외한다. 진단이 꺼져 있으면 이 타이머를 만들지 않는다. 입력 처리 구간과 프로세스 시작·종료 구간의 분위수는 각각의 분포이므로 더해서 전체 지연으로 해석하지 않는다.

## 실행 전 판정 기한

훅 클라이언트는 요청에 대기 기한(`deadline_unix_ms`, 기본 PreToolUse 15ms)을 실어 보낸다. 데몬은 실행 전 판정 중 파일을 읽는 단계(검증 근거 재사용 확인)를 이 기한에서 2ms를 뺀 시각까지만 진행한다. 끝내지 못하면 실행을 막지 않는다. 기한을 넘겨 계산된 판정은 클라이언트가 받지 못했을 수 있으므로 세션별로 세고, 상태줄에 `실행 전 판정 시간 초과 N건`과 `확인 불가`로 표시한다. 기한 필드가 없는 이전 클라이언트의 요청은 15ms 기한으로 처리한다.

이 기한 안에 끝날 수 없는 외부 검사기(iron-laws, 최대 수 초)는 실행 전 판정에 쓰지 않는다. iron-laws 결과는 쓰기가 끝난 뒤 비동기로 안내한다.

## 콜드 스타트

데몬 소켓이 없으면 훅 클라이언트는 데몬을 시작하고 최대 500ms의 연결 재시도 예산을 사용한다. 연결되면 **원래 첫 요청을 한 번 전송**한다. 요청을 쓴 뒤 응답이 없다고 다시 보내지는 않는다. 중복 도구 기록이나 사용자 의도 개정을 만들지 않기 위해서다.

이미 실행 중인 데몬에는 기존 짧은 훅 응답 기한을 적용한다. `SAMCHEONPO_NO_SPAWN=1`은 데몬 시작과 콜드 스타트 대기를 모두 건너뛰며, 연결 실패 시 바로 기존 허용 출력을 반환한다. 부팅이 재시도 기한을 넘거나 연결이 실패하면 첫 이벤트가 관측되지 않을 수 있다. 이를 정상 수신으로 주장하지 않는다. 프로세스 기동·OS 스케줄링 시간까지 포함한 엄격한 실시간 보장은 아니다.

## 버전 탐침

`<agent> --version`은 훅 처리와 데몬 전역 잠금 밖에서 실행한다. 프로세스에는 500ms 제한과 출력 파이프 종료 대기 50ms 제한을 적용하고, 최대 4KiB만 보관한다. 알려진 어댑터 이름만 실행하며 한 데몬에서는 에이전트별 한 번 탐침한다.

확인 전이나 지원 범위 밖 버전은 관찰 전용이다. 확인된 버전의 능력은 세션 잠금으로 반영한다. `AgentStatus` 소켓 요청은 확인 완료·버전·시험 범위 여부를 반환한다. 버전 문자열 확인은 바이너리 무결성이나 사용자 신원 인증이 아니다.

첫 계약 안내는 능력 확인 전에는 보류하고 지원되는 후속 훅에서 전달한다. 그 사이 목표가 바뀌거나 계약 상태가 전이되면 오래된 안내를 폐기한다. 보류된 계약 안내는 최신 것 하나만 유지한다.

## 확인한 범위

- 지연된 소켓 생성 후 첫 연결·첫 요청 전달, 정상 연결의 추가 데몬 기동 방지, 기동 실패 대기 상한 회귀 검사.
- 지연된 버전 탐침이 세션 생성·Ping을 막지 않는 검사, 확인 전 차단 금지, 최신 초안 전달 검사.
- 격리된 Linux 임시 홈·프로젝트의 실제 실행 파일에서 데몬이 없는 상태로 UserPromptSubmit을 전달했다. 단일 관측의 프로세스 포함 소요 시간은 약 40ms였고 `cmd card`에서 첫 요청의 작업 ID·개정·출처를 확인했다. 시험용 데몬은 Shutdown으로 종료했다.

## 큐 포화

작업 큐는 256개로 제한한다. 가득 차면 훅을 무기한 기다리게 하거나 고루틴·큐를 무제한 늘리지 않고 새 작업의 미처리 건수를 올린다. 접수된 작업은 종료 시까지 배출한다. 미처리 사건이 있는 세션에서는 훅 개입 출력을 보내지 않고 자동 검사·새 의미 판정을 중단하며 완료 조건 충족을 주장하지 않는다. 상태줄과 요약은 누락을 표시하고, 종료는 정상 영수증을 발행하는 대신 오류를 반환한다. 이미 시작한 외부 작업을 소급 취소한다는 보장은 아니다.

워커와 정상 종료 경로가 에이전트·세션별 누락 수를 원장에 단조 증가 방식으로 보존한다. 기록된 누락은 같은 세션으로 재시작해도 지워지지 않는다. 프로세스가 원장에 기록하기 전에 강제 종료되면 메모리의 마지막 누락 수까지 복구할 수 있다는 보장은 없다. 다른 세션 ID로 다시 시작해도 과거 세션의 누락이 해결된 것은 아니다.

## 상태 계산과 경량 실행 파일

상태줄의 토큰·미가격 토큰·낭비 환산액은 추가된 사건과 변경된 사용량만 반영한다. 뒤늦은 0원 사용량 갱신도 무효화 대상이다. 진척 경계가 바뀌면 유휴 토큰을 다시 계산한다. 변경 없는 조회는 O(1)이고, 사건별 집계 스냅샷은 O(n) 메모리를 쓴다. 이는 전체 탐지기의 모든 처리가 상수 시간이라는 뜻은 아니다.

`samcheonpo-hook`은 CLI·SQLite·모델 SDK를 가져오지 않는 별도 훅 전송 프로그램이다. 데몬 시작은 같은 디렉터리의 `samcheonpo`에 맡긴다. 설치 시 실행 가능한 형제 파일이 있으면 훅에 사용하고, 없으면 기존 메인 실행 파일을 쓴다. 두 파일은 같은 버전으로 배포해야 한다. 기존 설치를 자동으로 고치지는 않는다.

`samcheonpo bench-hook --n 200`은 임시 홈·프로젝트를 만들고 사용자 데몬과 분리한다. 첫 사용자 요청으로 데몬을 시작한 뒤 워밍업한 PreToolUse를 측정한다. 클라이언트 진단과 서버의 세션별 수신 수를 교차 확인하고, 빠른 fail-open을 성공으로 세지 않는다. 유효 표본 수는 1~10000이다. 사용한 실행 파일, 콜드 스타트, p50/p95/p99/최대, 응답·타임아웃·실패·첫 요청·도구 수신·큐 누락을 출력한다. 오류나 누락이 있거나 p95가 10ms를 넘으면 실패한다. 시험 데몬을 종료하며 종료 확인 실패 시 진단 디렉터리를 보존한다.

`SAMCHEONPO_HOOK_DIAGNOSTICS=1`은 훅의 전송 상태만 stderr JSON으로 출력한다. 프롬프트·도구 인자·응답 본문은 기록하지 않는다. `response_received`는 전송 응답을 받았다는 뜻이며 사용자 열람·실행·효과의 증거가 아니다.

2026-10-06 Linux/amd64 실제 실행 파일 200회 측정: 기존 메인 파일 경로는 p95 21.21ms로 실패했고, 경량 파일 경로는 p50 6.12ms / p95 8.68ms / p99 9.67ms / 최대 10.19ms였다. 후자의 콜드 스타트는 41.48ms, 응답·도구 수신 200/200, 첫 요청 수신 확인, 타임아웃·실패·큐 누락 0이었다. 이는 이 호스트의 관측값이지 모든 OS·부하에 대한 성능 보장은 아니다.

2026-10-07 같은 측정(load average 약 69): 현재 버전 p95 13.7–18.1ms, 같은 조건의 2026-10-06 버전 p95 12.8–16.3ms로 둘 다 10ms 목표를 넘었다. 변경에 따른 회귀로 볼 근거는 없지만, 부하가 낮은 환경에서 다시 측정하기 전에는 10ms 목표 충족을 주장하지 않는다. 상태 집계의 변경 없는 조회 벤치는 100개·10만 개 사건에서 각각 약 25ns, 할당 0이었다.
