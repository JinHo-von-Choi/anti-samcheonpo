# 목표 카드와 의도 개정

`samcheonpo cmd card`는 현재 관찰 중인 세션의 목표 카드와 최신 의도 출처를 표시한다. `contract show`는 세션 밖에서 현재 파일과 승인 상태를 보여 주며, 관찰하지 않은 과거 사용자 출처를 추측하지 않는다.

## 변경과 승인

첫 일반 요청은 신규 요청, 일반 후속 문장은 후속 설명으로 기록한다. 후속 설명은 이전 목표를 덮어쓰지 않는다. `목표 변경:`, `방향 변경:`, `Change goal:` 또는 `/samcheonpo:edit <내용>`은 명시적 방향 변경이다. 모호한 자연어를 자동으로 방향 변경으로 분류하는 모델은 사용하지 않는다.

방향 변경과 edit는 이전 계약의 검사·범위 승인을 먼저 보류한다. 계약 파일을 바꾸기 전 재수락은 거부한다. 파일이 바뀌었다는 것은 요청 의미가 정확히 반영됐다는 증명이 아니므로 새 계약 내용은 사용자가 확인해야 한다. 새 초안은 실행 승인이 아니며 수동 조건도 자동 완료가 아니다.

실시간 accept 명령은 승인한 계약 목표와 당시 검사 해시를 `confirmed_contract` 개정으로 기록한다. 그 개정도 `draft: true`이며, 이는 **의도 레코드 자체에는 실행 권한이 없다**는 뜻이다. 실제 권한은 별도 계약 수락 상태에서만 읽는다. 세션 밖의 `contract accept`는 파일 승인 절차이고, 실시간 사용자 이벤트가 있었다고 소급 생성하지 않는다.

## 출처와 원장

신규 요청·후속 설명·방향 변경·실시간 계약 확인에는 작업 ID, 연속 개정 번호, 부모 개정, 목표, 메시지, 입력 출처·세션·이벤트 식별자·관측 시간을 보존한다. 이벤트 식별자는 해당 세션에서 관측한 순번과 시각의 조합이다. 실제 인간의 신원을 인증하는 서명은 아니다. 도구 출력·가져온 문서는 사용자 출처로 변환하지 않으며, 자동 계속하기로 식별된 입력은 사용자 의도 개정으로 저장하지 않는다.

작업 생성·개정 추가·세션 연결은 하나의 SQLite 트랜잭션이다. 연결 실패나 다른 작업으로의 세션 재지정 충돌은 전체 저장을 롤백한다. 재시작은 기존 작업과 최신 개정을 복구한다. 연결된 프로젝트가 다르거나 원장이 모순되면 새 작업을 조용히 만들어 덮지 않고 오류를 반환한다.

계약 승인 파일과 SQLite는 분산 트랜잭션이 아니다. 변경 요청은 파일 승인을 먼저 보류한 뒤 의도를 기록한다. 그 사이 장애로 출처 기록이 빠질 수 있으며 저장 실패를 표시한다. 실패한 승인 보류를 이전 디스크 승인으로 되돌리지 않는다. 이 한계를 완전한 사건 기록으로 표현하지 않는다.

## 범위와 개인정보

현재 자동 연결은 한 에이전트 세션의 연속 작업·개정 기록이다. 다른 세션으로의 명시적 승계, 부모/자식 비용 중복 방지와 검증 근거 승계는 E8에서 처리한다. 사용자 메시지는 로컬 원장에 저장되며 목표 카드도 로컬 출력이다. 카드에는 작업 내용이 있으므로 영수증의 공유용 출력처럼 익명화됐다고 간주해서는 안 된다. 외부 업로드는 하지 않는다.
