# 2차 탐지 구현

2026-10-12. 분석기 `samcheonpo-eval/0.5.0`, 원장 스키마 `11`. 범위는 세션 간 자동 탐지, 요구사항과 실제 결과의 연결, 실행 가능한 후보 규칙의 독립 평가·승격이다.

## 실행 중 세션 간 반복

기존 task/session 링크를 사용한다. 같은 개정·대상·결과·입력·환경·실행 맥락·수락 권한을 가진 실패 또는 조사 결과가 2개 이상의 세션에서 3회 이상 반복되면 `s1.linked_loop` 후보를 기록한다. 다른 작업을 지문 유사성으로 합치지 않는다. `includes_children`의 중복 자손, 순환 링크·혼합 에이전트 ID, 성공 검사·결과 변화, 미상·flaky 관측을 보호한다.

훅에서 사건 저장 뒤 별도 읽기 전용 연결로 원장의 원자적 스냅샷을 읽는다. 작업당 최대 32개 세션, 세션당 최근 256개 사건, 실행 간격 2초, 읽기 시간 제한 2초, 동시에 한 작업으로 제한한다. 읽기·간격 대기 중 도착한 사건은 최대 128개 대상의 최신 트리거로 합쳐 다시 읽으며 첫 결과 외의 검사도 버리지 않는다. 세션 한도 초과는 판단을 유보하며 사건 창 일부가 생략됐으면 `window_truncated`를 표시한다. 창 안에 있는 긍정 반복 근거는 후보로 남길 수 있지만 전체 작업의 무반복이나 전체 비용을 확정하지 않는다. 사용량은 `observed_window` 기준이다.

로컬 이벤트 번호와 다른 세션의 에이전트·세션·이벤트 참조를 구분해 보관한다. 종료 시 취소하고 완료를 기다리며, 다른 의도 개정의 늦은 결과는 폐기한다. 동일한 발견을 중복 기록하지 않고 원장에 저장한 발견으로 재시작 후 중복도 막는다. 중복 키 캐시는 최대 128개다. 기존 회복 정책은 미완료 처방을 동시에 하나만 허용하므로 여러 발견 중 안내가 보류될 수 있다. 판정은 남기고 안내 보류 이유를 `recovery_unavailable`로 기록한다.

기본 기록 전용이며 사용자 설정의 `recommend_rules: [s1.linked_loop]`에서만 안내를 선택한다. L1 추정 안내, 귀속 비용 0이다. 이 결과로 실행을 차단하거나 인수인계를 실행하지 않는다.

## 요구사항·주장·결과 그래프

수락 또는 초안 계약의 완료 항목을 안정된 ID로 사용한다. 계약이 없으면 사용자 목표의 절에서 제한된 요구사항을 추정한다. 요구사항 최대 8개, 최근 사건 64개, 그래프 관측 24개를 보관한다. 추정·초안 항목은 실행 권한을 만들지 않는다.

관측 역할은 현재 사용자 요청, 명시적으로 수락한 확인, 에이전트 자기 보고, 도구 결과다. 파서와 훅에서 사용자 메시지와 메타 메시지를 구분한다. 완료 주장·부분 공개·승인 요청은 코드 블록을 제외한 문장에서 추출한다. 새 사용자 요청 전의 주장과 승인을 현재 요청의 근거로 재사용하지 않는다.

관련 검사 실패 또는 통과는 수락된 항목 ID, 현재 작업·개정·권한, 알려진 입력·환경, 완전한 관측이 모두 연결돼야 한다. 파일 활동은 모든 요구사항을 충족시키지 않으며 이전 검사 근거를 무효화한다. 관련성을 알 수 없는 새 검사는 이전 실패를 확정 모순으로 사용하지 못하게 한다. `passing_evidence_candidate`도 현재 완료를 보장하지 않는다. 최종 `completion`은 `unknown`이다.

선택형 의미 판정기는 이 그래프에서 역할·관련성·순서가 검증되는 쟁점만 후보로 만든다. 전체 완료 주장보다 나중의 실패로 과거 주장을 틀렸다고 판정하지 않는다. 구체적 연결이 없는 추정 항목이나 수동 완료는 미확인으로 유지한다. 모델 단독 차단과 근거가 없다는 이유만의 완료 부정은 허용하지 않는다. 제공자·모델·외부 전송은 기존 사용자 설정을 따른다.

수락된 요구사항의 최신 실제 실패 뒤에 전체 완료 주장이 나오면 모델 없이도 `s5.partial_done` 후보를 기록한다. 부분 공개·완료 부정·검사 실행만 완료했다는 보고·코드 문구는 제외한다. 기본 기록 전용 L1 추정이며 비용을 귀속하거나 차단하지 않는다.

HUD에는 그래프를, 원장·스냅샷에는 원문 대신 요구사항 ID·라벨 해시·상태·근거 번호를 저장한다. 네이티브 Claude/Codex의 읽기·검색 결과도 본문을 저장하지 않고 `observation_fp`를 계산한다. 셸은 출력 절단 전 지문을 계산한다. 기존 봉인의 정규 입력은 유지한다.

## 후보 규칙 설계와 독립 평가

`rules candidates`는 기존 집계 보고서다. 새 `rules propose`는 calibration 구간에서 실제로 재현되는 같은 결과의 반복을 고정 정의로 만든다. 정의는 증상, 도구, 조사/검사 구분, 반복 최소 횟수, 관측 창으로 제한한다. 자유 코드·정규식·셸 명령을 생성하거나 실행하지 않는다. 후보 최대 32개, 규칙별 창 최대 64개다.

제안 파일에 정의, 라벨·원장 출처 해시, `split/2` 해시와 평가 기준을 고정한다. 기본 기준은 Wilson precision 하한 0.90 이상, 오탐률 상한 0.05 이하다. 제안 후 라벨·원장·분할·기준 변경을 거부하며 실제 매처 입력의 선택 범위·불명확성·변경·백그라운드·오류 상태도 출처 해시에 포함한다. 해시는 추적과 변경 탐지용이며 라벨 작성자의 실제 독립성을 인증하는 서명은 아니다.

`rules evaluate`는 제안을 다시 검증한 뒤 holdout의 구간별 독립 라벨러 ID 최소 2명의 일치한 라벨만 평가한다. 라벨 없는 사건을 음성으로 간주하지 않는다. 같은 저장소 **또는** 과제 계열을 공유하면 하나의 연결 그룹을 신뢰구간 단위로 쓴다. 의견 불일치·라벨 부족·양음성 혼합 그룹·구간 누락은 미상이며 미상 그룹이 있으면 승격하지 않는다. `public_regression`은 승격에 사용할 수 없고 `preregistered_holdout`만 통과할 수 있다. 라벨러 ID와 사전 등록 선언의 진정성은 별도 운영 검증이 필요하다.

`rules promote`는 평가 JSON의 통과 문자열을 믿지 않고 원래 라벨·원장으로 평가를 재계산한다. 통과해야 접근 제한 0600 파일로 팩을 생성한다. `--install`은 사용자 전용 `learned-rules.json`에 기록 전용으로 설치하고 설정·데몬을 변경하지 않는다. 사용자 `recommend_rules`에 출력된 정확한 규칙 ID를 넣어야 안내한다. 프로젝트 설정이 권한을 추가하지 못한다.

설계 증거 재생, 독립 평가, 네이티브 분석, 실행 중 탐지는 같은 `rulepack.Matcher`를 사용한다. 설치된 팩은 새 세션에서 읽으며 분석 CLI도 사용자 팩을 읽는다. 합성 벤치마크 라이브러리는 명시적으로 받은 팩만 사용한다. 통과 팩도 `effectiveness: unvalidated`이고 L1 추정·비차단·비용 미귀속 원칙을 유지한다. 비용 절감과 완료율의 인과 효과는 별도 A/B 검사 대상이다.

```sh
samcheonpo rules propose --labels labels --split split.json --out proposal.json
samcheonpo rules evaluate proposal.json --labels labels --split split.json --out evaluation.json --check
samcheonpo rules promote proposal.json --labels labels --split split.json --out rulepack.json
# 사용자에게 설치가 필요한 경우에만 선택:
samcheonpo rules promote proposal.json --labels labels --split split.json --install
```

닫힌 세션 또는 audit 세션만 학습 자료로 읽는다. 조회는 원장을 생성·마이그레이션하지 않는다. 이번 구현 작업에서는 실제 사용자 팩 설치, 실행 파일 교체, 데몬 재시작, 외부 판정기 활성화는 수행하지 않았다.

## 효과 검증

합성 라벨과 네이티브 로그 재생은 구현의 정확한 동작을 검사한다. 사람 독립 라벨 코퍼스의 실사용 오탐률·완료율·총비용 절감률을 입증하지 않는다. 검증 명령과 환경 제약은 [2차 검증 기록](../benchmarks/2026-10-12-phase2-validation.md)에 남긴다.
